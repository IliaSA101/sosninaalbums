## Автосборка (`PlanGroups`, спека 027)

Делит n фото по порядку ровно на N разворотов, в каждом не больше m фото (`layout.PlanGroups(aspects, p, N, m)`; N зажимается в `SpreadRange(n, m)` = [⌈n/m⌉, n], m — в 1…`MaxPhotos`). Динамическое программирование по префиксам на ровно N групп: `best[c][j] = max_k best[c−1][j−k] + k·score(j−k..j) − 0.12·(k − n/N)²`. Вес `k·score` не даёт выгоды дробить на мелкие развороты, штраф держит размеры около среднего. Окна длиной k ≤ `kmax` = min(m, 64, 2·⌈n/N⌉ + 2); оценка окна до 7 фото — лучшая раскладка (`Cached(…, 1)`), с 8 — быстрая (ряды на страницах, `planfast (planWork.window, бывший quickScore)`). Матрица оценок окон считается параллельно и кэшируется (последние 4 набора), недостающие столбцы досчитываются, когда N уменьшается: повторный вызов с другим N стоит только DP (миллисекунды). Итог — `Plan{Groups, Spreads, Min, Max, Avg}`.

В альбоме (`album/spreads/plan.go`) подсказка и сборка идут через один `PlanJob` (`PlanOf`): фото из сеток и с фонов отсеиваются, пропорции — как их увидит сборка после `Remember` (размеры из `PhotoInfo`, поворот — у фото, уже стоящего в альбоме). `Editor.AutoPlan(photos, N, m)` снимает вход под замком и считает вне его; верх ползунка — min(n, `MaxSpreads` − непустых разворотов; пустой хвост свободен), альбом полон (верх < низа) — ошибка про 1000 разворотов, фото нет — пустой план. `Editor.AutoBuild(photos, at, N, m)` с теми же аргументами делает ровно те же развороты (`TestAutoPlanMatchesBuild`), одним шагом undo. Сборка «в конец» (UI шлёт `at = len`) занимает сплошной пустой хвост (`Spread.Empty()`: разворот без фото, названия, цвета, сетки, виньетки): новые встают на его место, `AutoPlan.reuse` = min(хвост, N), верх ползунка считает хвост свободным; пустые в середине и «не пустые» развороты не трогаются (035 U1). Окно показывает «В альбоме станет …» по `reuse`, хвост на фронте не считается. Перестановок в автосборке нет; раскладку каждого разворота потом считает прежний путь (`Layouts`, лучшая).

## Разнообразие (`internal/layout/variety`, спека 041)

Уровень `model.Variety` — «Меньше / Обычное / Больше» (ручка в «Дополнительно» окна автосборки, `AutoOpts.Variety`). Фото по разворотам (`PlanGroups`) от уровня не зависят; меняется только выбор раскладки каждого разворота.

- **«Меньше»** — как 0.10: лучшая раскладка, в файле `""` (`TestAutoBuildVarietyLessSame`).
- **«Обычное» / «Больше»** — `variety.Pick` идёт по развороту вместе с соседями, раскладка пишется в `Spread.Layout` обычным ключом (формат файла не меняется, признака «выбрано сборкой» нет — №18, №35). Допуск потери оценки — δ (со звездой δ★, для воздуха свой).
- **Ритм** (№34, №60): период R = 4 («Обычное») / 3 («Больше»). В ритме — воздушный разворот (до 12 / 16 фото, одна или обе страницы поменьше) и разворот с главным фото; вне периода — только при сыром `Score ≥ best − 0.02`. Два главных подряд нет, семейство прошлого главного получает штраф 0.5, раскладка с главным не повторяет вид соседа даже со звездой. «Главное» определяется по геометрии, в том числе пара крупных (№58). Звезда (4★/5★, свои или Lightroom) делает фото главным, если вариант не намного хуже лучшего (№33, №59); без звёзд главное появляется само.
- **Новизна вида** (№61): вид — картинка (2×2 «рядами» и «столбцами» — один вид). Совпадение с соседом и позапрошлым запрещено по возможности; вид, бывший в цепочке раньше, — штраф 0.25; тот же ключ, что у предыдущего, при другом виде — штраф 1.0. Итог на 96 горизонтальных: 11 видов, соседей с одним ключом 24 («Меньше» — 87).
- **Пул** (№62): `Pool` = ряд «Авто» + «Другие варианты» в их порядке; выбор сборки видит только то, что видно в подборке и счётчике (№38). С 17 фото «Других вариантов» нет (№37).
- **Генератор раскладок с главным фото** (`featured.go`, 8–16 фото, №57, №68): главное в любой позиции ленты, без обрезки, ключи нынешней грамматики через `layout.Build`; в ряд «Авто» и в `Layout ""` не попадает. Звезда судится по `Fair` (№59).
- **Листание** (№36): пробел и ‹ › идут по ряду «Авто», затем по «Другим вариантам»; счётчик «Раскладка i / N» — по объединённому ряду.
- **«Разнообразить раскладки»** (`spreads/vary.go`, `Editor.VaryLayouts`): то же правило над выделенными «Авто»-разворотами с учётом соседей; сетки и виньетки не трогаются, один шаг undo.
