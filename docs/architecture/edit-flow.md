## Поток правки

Устройство `internal/album` (спека 023): правка проекта идёт только через `Editor`. Метод `Editor` в ядре — обёртка (охранная проверка аргументов и `return e.change(func(p) { grid.SetPlaces(p, …) })`, тело ≤ 3 операторов), тело операции — экспортная функция области над `*model.Project` (`grid`, `design`, `layers`, `backdrop`, `spreads`, `cover` — обложка 032, `names` — поля подписей 030: имена, вставка списка, стиль листа; генератор мест виньетки 031 — `vignette`, чистая геометрия без проекта; чтение — `view`; файл — `salbum`; карта — `internal/album/doc.go`). Вне дерева `album` пакеты областей (`grid`, `design`, `layers`, `backdrop`, `spreads`, `view`) импортировать нельзя — правило depguard «области альбома — только из дерева альбома» (конфиг линтера): тело правки без проверок обёртки обошло бы undo, no-op и `Normalize`; сборка вида — через `Editor.View`. `model` и `salbum` снаружи доступны, но forbidigo закрывает в `model` вызовы, которые правят проект мимо Editor (`model.Unmarshal`, `Remember`, `Project.SetFrom/SetLoaded/Normalize/KeepLayouts/Detach`, `Spread.Insert`, `Mark.WithAlt`): вне дерева `album` они запрещены, а крючки тестов `model.SetMarksLimit` и `model.SetParallelLayouts` — вне `_test.go`. Пакеты `prefs` и `export` импортируют только `model`/`salbum` (`export` — ещё ядро `album`, но только в тестах: рабочему коду отдают `Snapshot` и `View`). Доступ тестов к состоянию Editor — `album/internal/inside` (из рабочего кода дерева не импортируется, кроме `inside.go`) и помощники `album/internal/edtest` (только `_test.go`); страж `TestNoExportedGlobals` не даёт завести экспортные глобальные переменные: крючки и таблицы — функции (`model.PlainStyle()`, `model.BdScopes()`), порог `slowOp` меняется через `inside`/`edtest`. Живой `Project` есть только у ядра: `NewEditor(p, path) (*Editor, error)` и `Restore(q)` берут свою копию и перепроверяют пути (`own` → `salbum.Check`), `Ref`/`Refs` отдают глубокую копию (`PhotoRef.Copy`); типы биндингов Wails (`View`, `Box`…) живут в `model`, потому что namespace берётся из имени пакета. Конвейер `Editor.edit` встроен в ядро: снимок, `fn`, затем `settle` (`editor.go`): `SyncGrid(false)` → `PruneRefs` → `Normalize` → `KeepLayouts` → `design.Rescale` → `grid.Rescale` → `backdrop.Rescale` → `cover.Reflow` (зоны обложки сменились — содержимое едет по зонам, 032 §3) → `FixVignettes` (инварианты вида и ролей виньеток, 031) → `grid.Relay` (пересборка нетронутых виньеток при смене настроек или стиля подписей — после всех пересчётов формата, иначе места масштабировались бы дважды) → `FitTexts` → `SyncOrder` → `CheckTotals` (`Normalize`, `KeepLayouts`, `FixVignettes`, `SyncOrder`, `FitTexts`, `SyncGrid`, `PruneRefs`, `CheckTotals` — методы `model.Project`; `Restore` (`whole`) пропускает всё от `Normalize` до `grid.Relay`). Его же зовёт сухой прогон `PreviewVignette` над копией — предпросмотр окна виньетки по построению равен итогу «Применить».

UI-действие → `store` → `Api.Method(...)` → `App.Method` → `Editor.change(fn)` → новый `View` → `App.changed` (таймер автосохранения, событие `view`) → ответ уходит в `store.apply(view)` → интерфейс перерисован.

`Editor.change` делает снимок проекта, применяет `fn`, проверяет сетки (`SyncGrid(false)`: место с ушедшим фото пустеет, фото без места садится в первое пустое, пустых нет — отказ «На развороте нет свободных мест», правка откатывается), чистит `Photos` от неиспользуемых (`PruneRefs`), приводит в порядок (`Normalize`: удаляется разворот, с которого правка унесла фото и он `Spread.Empty()` — нет ни фото, ни текстов, ни мест, ни фона, ни названия; созданный пустым (`NewSpread` без фото, спека 013) живёт: его `Photos` не меняются; тот же предикат у `dedupe` (`salbum/fix.go`)), сохраняет раскладки (`KeepLayouts`: у разворота, где поменялся состав или геометрия страницы, а число фото то же, остаётся прежний ключ, если `Build` строит его для нового состава; иначе лучшая; цвет и dpi раскладки не перепроверяют; сетки пропускаются), при смене формата сдвигает тексты и места пропорционально (`design.Rescale`, `grid.Rescale`; фон — `backdrop.Rescale`) и держит тексты внутри разворота (`FitTexts`: блок «по тексту» (`auto`) получает ширину `model.AutoW` — естественная ширина `text.NaturalWidth` + 0.01, не шире `model.TextMaxW` = страница без безопасных полей, — точка выравнивания при этом стоит; повёрнутый блок держится по описанному прямоугольнику со сдвигом, округлённым внутрь до 0.01; функция идемпотентна). Если проект байт-в-байт не изменился (no-op), в undo ничего не попадает. Подряд идущие правки с одним ключом `lastMerge` — один шаг undo: `layout:<разворот>` (листание и выбор раскладки), `text:<сессия>` (`AddText`, `SetText`, `SetCaption` одной сессии ввода; сессию создаёт интерфейс, ≤ 32 знаков `[A-Za-z0-9-]`), `grid:<сессия>` (`SetPlaces` — серия стрелок); если слитая цепочка вернула проект к началу (блок добавили и стёрли), шаг убирается. `View` (`album/ops_view.go`, сборка — `album/view`, типы — `model/viewtypes.go`) содержит готовые прямоугольники каждого фото в мм и действующий ключ раскладки, а также `frames` (фото целиком по кадру и эффективный dpi), `texts` и `captions` (рамка и строки в мм разворота, переносы — `text.Cached`), `bg`/`bgSet` (цвет страниц: свой → альбома → белый), `flipH`/`flipV` у `FrameView` (зеркало фото), `name` разворота, у текста `rot` (поворот вокруг `x, y` — угла рамки до поворота; строки без поворота) и `auto`, `textMaxW`, `minDPI`/`lowDPI` (кадры и фото фона ниже порога; по развороту — `SpreadView.lowDPI`, спека 028), `grid`/`places`/`emptyPlaces` (ручная раскладка, ниже): интерфейс ничего не считает.

Отмена: один хронологический стек, ≤ 200 шагов со снимком альбома (`undoAlbum`) и отдельно ≤ 2000 шагов только своих отметок (`MaxMarkUndo`: серия оценок не вытесняет правки вёрстки), сверх — уходит самый старый шаг своего вида (`dropUndo`); общий вес ≤ `maxUndoBytes` = 256 МБ (последний шаг остаётся всегда).

Свои отметки фото (спека 004, `album/editor_marks.go`) живут в `Editor.marks` (ID фото → `Mark{path, rating, label, flag}`, `nil`-поле — «не трогали, действует отметка из файла»), а не в `Project`: иначе тысячи отметок платили бы marshal/unmarshal на каждой правке альбома. Правка отметок идёт мимо `change`, но с тем же контрактом: шаг отмены — дельта `Snap{Marks: []MarkChange{id, before, after}}` (без снимка проекта, вес `MarkBytes` = 176 на запись), холостая — ни шага, ни `rev`, ни `dirty`; иначе `rev++`, `marksRev` из общего для процесса счётчика (у нового проекта другой), `dirty`, `redo = nil`, цепочка `lastMerge` рвётся. `Undo`/`Redo` применяют `before`/`after` и меняют `marksRev`. `SetMarks(photos, patch)` по каждому фото и полю: цель из патча (`step` — ±1 от действующей в пределах 0–5, `toggle` — снять метку, если у всех она уже этого цвета); своего поля нет и цель равна отметке из файла — поле не пишется; недопустимое поле патча отбрасывается, остальные применяются; запись без полей удаляется; сверх `MaxMarks` = 100 000 — ошибка, отметки прежние. Действующая отметка — `model.Effective(own, xmp)`, зеркало во фронте — `markOf`, паритет `testdata/parity/marks.json`. Отметки фото ленты, а не только альбома: `PruneRefs`, `RemovePhotos`, `RemoveFolder`, `DeleteSpread`, `AutoBuild` их не трогают; перепривязка (`Relink*`) переносит путь и ID отметок в том же шаге отмены (`Snap` с `P` и `Marks`); `Restore` заменяет их целиком.

Исключение «мимо `change`» кроме отметок: `Editor.SyncOwnNames(tpls)` (решение 0.11 №67) — имена своих шаблонов виньетки (`Vig.Own.Name`) по файлу `templates.json` в проекте и во всех снимках отмены и возврата. Имя шаблона живёт в файле шаблонов и отмены не имеет, поэтому шага нет, `Undo`/`Redo` не сбрасываются (`redo` не обнуляется), `settle` не нужен; `rev` и `dirty` — только если изменился сам проект (изменились лишь снимки — вид не меняется); вес снимков (`N`, `undoBytes`) пересчитывается по разнице длины JSON. App зовёт его после `RenameGridTemplate` и перед `DeleteGridTemplate`.
