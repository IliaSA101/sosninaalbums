## Экспорт

`Export(ExportOptions)` (окно `ExportDialog`; `app/export_plan.go`: `range` — «3-5, 8, 7п» через `export.ParseRange`, `internal/export/ranges.go`, `Unit{Spread, Page}`: `7л`/`7п` — левая/правая страница; примеры общие для Go и UI — `testdata/parity/ranges.json`, `export/exportrange.ts`; `quality` 100/95/80, `dpi` 72..1200, 0 — из альбома; `pages` — вид «По страницам», файлы `NN-1.jpg`/`NN-2.jpg`, иначе `NN.jpg`) спрашивает папку, снимает `Snapshot` проекта и в горутине рендерит развороты: холст `px = мм/25.4·DPI`, белый фон, каждое фото — `Fill` (с центровкой) в свою ячейку (зеркало `FlipH/FlipV`: окно кадра берётся из отражённой внутри `Img` видимой части — `2·Img.X + Img.W − c.X − c.W`, готовая ячейка переворачивается `imaging.FlipH/FlipV`, как на экране) (картинка с альфой — `draw.Over` на залитый фон страницы, непрозрачная — `draw.Src`; `fit: contain` сетки — фото целиком по центру места, поля — фон страницы: назначение = пересечение ячейки с `Img`). Фото готовятся параллельно (до 3 готовых ячеек в памяти: слот семафора берётся по порядку мест до `go`), а на холст ложатся строго по очереди `done[i-1]` → `done[i]`. Повороты (`render.Photo`: `Rot` — поворот места вокруг центра ячейки = `FrameView.CellRot`, `ImgRot` — фото вокруг центра `Img` = `FrameView.R`; порядок: зеркало в осях фото, `ImgRot`, `Rot`): `fold` сводит `Rot`, кратный 90°, в `ImgRot` (ячейка снова прямая, при нечётной четверти стороны меняются). Путь 1 — ¼ оборота: `prepare` + `imaging.Rotate`, Lanczos без маски. Путь 2 — наклон при прямой рамке, закрывающей фото: `Transform` прямо в ячейку холста (`render/rotated.go`, `prepareRot`). Путь 3 — поворот места или край фото внутри рамки (contain с наклоном): `Transform` во временный RGBA полосами по ядрам и `DrawMask` со сглаженной маской «рамка ∩ фото» (`framePoly`, `clipPoly`); повёрнутое фото на фоне — тот же путь с клипом области (`backdropPhoto`). Наклон фото фона (спека 045: `render.Backdrop.ImgRot` = `BackdropView.Frame.R`, `export/album.go` → `backdrops`): при прямой рамке ячейка — вся рамка, клип — область, путь 2 без маски; при повёрнутой `fold` складывает углы — путь 2 (рамка под ¼ оборота) или 3; без наклона — прежний путь байт-в-байт (эталон экспорта старых альбомов не меняется). Замер (i5-11400H): фон 600×300 мм, 300 dpi, 6000×4000, наклон 4,5° — около 0,65 с на разворот (`BenchmarkRenderBackdropTilt`, бюджет 3 с). Прозрачность фона (`Backdrop.Fade` → `Photo.Fade`, спека 017): `fadeAlpha` умножает альфу готового окна на `round(255·(1−fade))/255` (путь 1 — в `prepareSafe` после `prepareFn`, пути 2–3 — в `prepareRot`), дальше `draw.Over` на залитый цвет страниц — как CSS `opacity` на экране; `fade = 0` — прежний вывод байт-в-байт, `fade = 1` — фон не рисуется и файл не открывается. Фото и тексты рисуются одним стеком по `Z` (`Photo.Z`, `TextDraw.Z` из `View`; при равных — фото, затем тексты по порядку), пустые места не передаются. Пустые места сетки не передаются — там фон. Выгружается каждый разворот (пустой — один фон), номер файла = номер разворота в альбоме. Текст рисуется в своём слое стека контурами глифов (`text.Draw`, кернинг как в `Layout`); блок поворачивается на `TextDraw.Rot` (= `TextView.rot`, градусы по часовой вокруг левого верхнего угла рамки `X, Y`), подписи — всегда 0. Файлы называются `01.jpg, 02.jpg…` (`export.FileName`: при 100+ разворотах `001.jpg`; `00.jpg` — обложка (032, ниже); без обложки программа его не пишет). Порядок сегментов: JFIF с DPI, COM «Sosnina Albums» (метка «наш файл», `export.IsOurs`), APP2 ICC sRGB (`colorspace.SRGBProfile`, CC0), качество 95. Холст > 65535 px по стороне или > 400 Мп отклоняется (нужно меньше DPI). Прежние файлы цели (`export.StaleNames`: например `02.jpg` при переходе на `02-1/02-2`) удаляются только после записи новых и после подтверждения; файлы вне плана не трогаются, полный экспорт убирает и хвосты. Файлы пишутся через `.tmp` + Sync + Rename (`library.WriteFileAtomic`); `Trim` удаляет `.tmp` старше часа. Фото на фоне (`BgPhoto*`) рисуются под местами: рамка с поворотом и зеркалом, обрезка областью (разворот или страница); их файлы входят в проверку «пропавших» — отказ до диалога папки со списком, старые файлы целы.

Обложка (032 G3, U3; решение 72): `ExportOptions.cover` / `coverOnly` (окно — строка «Обложка», флажки «Обложка (00.jpg)» и «Только обложка»; `coverAvailable` в `exportopts.ts`). Лист обложки (`View.cover.sheet`, ID "cover") — первый шаг плана, файл `00.jpg` при любом числе разворотов (`export.CoverName`), прогресс общий N+1; рендер тот же, размер — из `Geo` обложки (сторонки, корешок, заворот). `coverOnly` включает обложку и игнорирует диапазон; без обложки и в проекте-листе 031 оба флага игнорируются; альбом без разворотов, но с обложкой, выгружается (в UI — `store.sheets.length`). «По страницам» обложку не делит. Свой `00.jpg` (с меткой) заменяется после вопроса, чужой — отказ; без обложки в плане `00.jpg` не трогается. `BlankCover` — пустая обложка (вопрос, как у разворота; печатью считаются свой цвет страниц и плашка корешка `SpineBg`), `FieldsWarning` — пустые поля подписей 030 по всем листам вида. Лист виньетки (031, `Settings.sheet`): страниц нет — вида «По страницам» и `7л`/`7п` нет (окно прячет «Вид», `7п` отклоняет Go), файл на лист.

Папка экспорта разбирается чистой `export.PlanDir` (`internal/export/dir.go`; план целей — `export.Plan`, `plan.go`): `ours` — `spread_NN.jpg` прежнего экспорта и `NN.jpg` (две цифры и больше: при ≥ 1000 разворотов `0001.jpg`) с меткой (их заменяем после подтверждения, удаляются только они), `foreign` — `NN.jpg` без метки (кроме `00.jpg`; для частичного экспорта задевают только файлы выбранных целей: `Plan.hitsFile`): экспорт отказывает и ничего не удаляет, чужие фото с таким именем невозможно потерять. Перед диалогом папки `colorReport` считает профили альбома: есть фото `other` — вопрос (`export.ColorWarning`, по умолчанию «Нет»); за ним, тоже до выбора папки, — пустые развороты из плана (`internal/export/blank.go`: `BlankSpreads` по `View` — без фото, текстов, подписей, фона-фото, мест и своего цвета; название не печатается и не мешает), вопрос «Разворот 5 пустой — выгрузить белым?» (не белый фон альбома — «с фоном альбома»), «нет» — экспорт не идёт; `adobe` вопроса не вызывает, пустые места сетки (`View.EmptyPlaces > 0`) — вопрос «На разворотах 3, 7 пустые места (5). В файлы они не попадут, там будет фон. Выгрузить?» (`export.EmptySummaryFor`/`EmptyWarning`, `internal/export/album.go`, больше 10 номеров — «…и ещё K»; после выбора папки, до вопроса о перезаписи), сводка уходит в `export:done` третьим аргументом (`note`) и в лог. Прогресс — события `export:progress`/`export:done`. Флаг «идёт экспорт» ставится до диалога папки; если в папке есть файлы прежнего экспорта (`ours`), спрашивается подтверждение перезаписи. Go помнит папку последнего экспорта, `ShowInExplorer()` открывает её (путь от интерфейса не принимается). `ShowPhotoInExplorer(id)` (`app/reveal.go`; запуск проводника — `internal/osx`) показывает файл фото альбома: путь только из проекта (`Editor.Ref`), `CheckLocalPath`; файла нет — открывается папка, нет и её — ошибка; запуск через подменяемую `revealPath` (= `osx.Reveal`); `ShowInExplorer` зовёт `osx.OpenDir`.

Режим «Для Фотосферы Pro» (спека 047; `ExportOptions.fsfera`, пакет `internal/export/fsfera`, `internal/app/export.go`). Первым, до всех вопросов, `fsfera.Check(p, путь альбома)` строит `Plan` (формат, тип листов, число разворотов, корешок, предел, имя папки, `Block` — запреты, `Warn` — предупреждения, `Memo` — памятка): непустой `Block` — ошибка вызова (строки через «. »), ничего не спрашивается и не пишется. Запреты: лист 031, страница не из таблицы форматов, нет разворотов, обложка не по шаблону / со своими размерами / не «Фотосферы», разворотов больше предела таблицы. Затем настройки окна заменяются заданными: все развороты целиком (`Range`, `Pages`, `CoverOnly` игнорируются), 300 dpi, с обложкой; качество остаётся выбором окна. Порядок вопросов: цвет → пустые развороты → пустые поля подписей → «Обложки нет … Выгрузить без обложки?» (в обычном экспорте на этом месте — «Обложка не по шаблону … Выгрузить как есть?» по `CoverView.Fix`) → выбор папки («папка книги будет внутри») → пустые места → перезапись своих файлов → посторонние файлы. Папка книги: имя берёт `fsfera.FolderName` из файла альбома через `paths.FolderName` (запретные знаки, CON/NUL, точки по краям, ≤ 64 знаков; несохранённый альбом — «Альбом»); `fsfera.BookDir` — выбрана сама папка книги (имя без учёта регистра) — пишем в неё, иначе `выбранная/имя`; проверка `Lstat` + `ModeDir`: файл, ссылка или junction на месте папки — отказ. Новая папка создаётся `os.Mkdir` только после всех вопросов, чтобы «нет» не оставило пустой папки. Посторонние файлы (`fsfera.Extra`: обычные файлы, кроме своих файлов прежней выгрузки, имён этой записи и служебных `desktop.ini`/`Thumbs.db`/скрытых с «.») — вопрос «В папке «…» есть посторонние файлы (N шт., например …): Фотосфера загрузит их вместе с альбомом. Продолжить?»; остаток записи `*.tmp` (`05.jpg.<число>.tmp`) — посторонний, загрузчик его возьмёт. Выгрузка без обложки удаляет свой `00.jpg` прежней выгрузки после записи (`fsfera.OldCover`, по метке программы; чужой `00.jpg` — посторонний, его не трогаем). По завершении `export:done` несёт четвёртым аргументом `memo` (`Plan.Memo`) — фронт открывает окно «Готово для Фотосферы» с кнопками «Открыть папку», «Открыть Фотосферу» (`App.OpenFsfera`, адрес калькулятора — константа в Go) и «Готово»; ошибка выгрузки — прежний тост. Проект экспорт не меняет.

Форма места (спека 044; `internal/render/shape.go`): `export` собирает `render.Photo.Outline` (`geom.Outline{Oval, Radius}`) из `FrameView.Shape/Radius` (`export/album.go`). Маска формы — контур кубическими Безье (эллипс или скруглённый прямоугольник, дуги по 45°) в `vector.Rasterizer`, сглаживание то же, что у пути 3; поворот места применяется к контрольным точкам. Путь 1 (поворот 0 или кратный 90°): ячейка готовится как раньше (Lanczos сохраняется), затем `blitMasked` кладёт её на холст через маску формы, маска считается от рамки места, а не от «Целиком»-окна. Путь 2 (быстрый, без поворота, рамка внутри фото) с формой не применяется: место с формой уходит в путь 3, где маска формы умножается на маску полосы (`drawShape`). Место без формы идёт прежними путями побитно так же (`TestGoldenExport` не менялся).

`App` живёт в `internal/app` (в корне только `main.go`: встраивает фронт и `wails.json`, зовёт `app.Run`) и разрезан по файлам: `app.go` (тип, старт, окно Wails и `Run`, ротация `log.txt` на 2 МБ), `api.go` (состояние, папки, отмена, режим «Сетка» и шаблоны, имена, листы виньетки и обложки), `decor.go` (библиотека фонов и стикеров, постановка и замена стикера, фото на фоне), `edit/` (подпакет: методы правок без своих данных и без типа результата `app`, встроен в `App`; рамка и вид стикера — `edit/sticker.go`), `namesfile/` (чтение таблицы с именами), `library.go` (`/media`, шрифты, сканирование, недостающие, перепривязка), `files.go` (файлы, автосохранение, резервные копии, настройки, «Последние»; логика `config.json` — `internal/prefs`), `export.go` (методы `Export`, `ShowInExplorer`; логика экспорта — `internal/export`). Текущий `Editor` лежит в `atomic.Pointer` (`App.editor()`): «Новый»/«Открыть» подменяют его, пока `/media` и автосохранение читают.

Фоны из библиотеки (спека 048 Ф1): узоры областей рисует `render` (`Spread.Patterns`, `PatternDraw{Kind, Inks, Scale, Seed, Fade}` — после заливки страниц, до фото фона; `gen.Spec` собирает `render`, решение №176), сцену — `export/album.go` из `SpreadView.Patterns`; лист с узором не пуст (`blank.go`). Свой фон — обычное фото фона, путь — из `Photos` (файл в библиотеке). `export.MissingPhotos`: своё без файла в библиотеке останавливает выгрузку отдельной строкой — «загрузите тот же файл», без «Найти пропавшие фото…».

Обрез и разметка типографии (спека 066, 0.15) в экспорт не входят: страница по-прежнему включает вылет, `settings.bleed` (розовая полоса `View.bleed`) и разметка разворотов/обложки (`View.spreadMarkup`, `CoverView.markup`, подложка PSD/JPEG/PNG и направляющие) — только экран; `export` собирает кадр из `View` и этих полей не читает (JPEG без подложки и полос). Сведение разметки с макетом — по глазам, в программе: «Вид ▸ Разметка типографии».
