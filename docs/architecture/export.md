## Экспорт

`Export(ExportOptions)` (окно `ExportDialog`; `app/export_plan.go`: `range` — «3-5, 8, 7п» через `export.ParseRange`, `internal/export/ranges.go`, `Unit{Spread, Page}`: `7л`/`7п` — левая/правая страница; примеры общие для Go и UI — `testdata/parity/ranges.json`, `export/exportrange.ts`; `quality` 100/95/80, `dpi` 72..1200, 0 — из альбома; `pages` — вид «По страницам», файлы `NN-1.jpg`/`NN-2.jpg`, иначе `NN.jpg`) спрашивает папку, снимает `Snapshot` проекта и в горутине рендерит развороты: холст `px = мм/25.4·DPI`, белый фон, каждое фото — `Fill` (с центровкой) в свою ячейку (зеркало `FlipH/FlipV`: окно кадра берётся из отражённой внутри `Img` видимой части — `2·Img.X + Img.W − c.X − c.W`, готовая ячейка переворачивается `imaging.FlipH/FlipV`, как на экране) (картинка с альфой — `draw.Over` на залитый фон страницы, непрозрачная — `draw.Src`; `fit: contain` сетки — фото целиком по центру места, поля — фон страницы: назначение = пересечение ячейки с `Img`). Фото готовятся параллельно (до 3 готовых ячеек в памяти: слот семафора берётся по порядку мест до `go`), а на холст ложатся строго по очереди `done[i-1]` → `done[i]`. Повороты (`render.Photo`: `Rot` — поворот места вокруг центра ячейки = `FrameView.CellRot`, `ImgRot` — фото вокруг центра `Img` = `FrameView.R`; порядок: зеркало в осях фото, `ImgRot`, `Rot`): `fold` сводит `Rot`, кратный 90°, в `ImgRot` (ячейка снова прямая, при нечётной четверти стороны меняются). Путь 1 — ¼ оборота: `prepare` + `imaging.Rotate`, Lanczos без маски. Путь 2 — наклон при прямой рамке, закрывающей фото: `Transform` прямо в ячейку холста (`render/rotated.go`, `prepareRot`). Путь 3 — поворот места или край фото внутри рамки (contain с наклоном): `Transform` во временный RGBA полосами по ядрам и `DrawMask` со сглаженной маской «рамка ∩ фото» (`framePoly`, `clipPoly`); повёрнутое фото на фоне — тот же путь с клипом области (`backdropPhoto`). Прозрачность фона (`Backdrop.Fade` → `Photo.Fade`, спека 017): `fadeAlpha` умножает альфу готового окна на `round(255·(1−fade))/255` (путь 1 — в `prepareSafe` после `prepareFn`, пути 2–3 — в `prepareRot`), дальше `draw.Over` на залитый цвет страниц — как CSS `opacity` на экране; `fade = 0` — прежний вывод байт-в-байт, `fade = 1` — фон не рисуется и файл не открывается. Фото и тексты рисуются одним стеком по `Z` (`Photo.Z`, `TextDraw.Z` из `View`; при равных — фото, затем тексты по порядку), пустые места не передаются. Пустые места сетки не передаются — там фон. Выгружается каждый разворот (пустой — один фон), номер файла = номер разворота в альбоме. Текст рисуется в своём слое стека контурами глифов (`text.Draw`, кернинг как в `Layout`); блок поворачивается на `TextDraw.Rot` (= `TextView.rot`, градусы по часовой вокруг левого верхнего угла рамки `X, Y`), подписи — всегда 0. Файлы называются `01.jpg, 02.jpg…` (`export.FileName`: при 100+ разворотах `001.jpg`; `00` — под обложку из шаблона типографии, программа его не пишет). Порядок сегментов: JFIF с DPI, COM «Sosnina Albums» (метка «наш файл», `export.IsOurs`), APP2 ICC sRGB (`colorspace.SRGBProfile`, CC0), качество 95. Холст > 65535 px по стороне или > 400 Мп отклоняется (нужно меньше DPI). Прежние файлы цели (`export.StaleNames`: например `02.jpg` при переходе на `02-1/02-2`) удаляются только после записи новых и после подтверждения; файлы вне плана не трогаются, полный экспорт убирает и хвосты. Файлы пишутся через `.tmp` + Sync + Rename (`library.WriteFileAtomic`); `Trim` удаляет `.tmp` старше часа. Фото на фоне (`BgPhoto*`) рисуются под местами: рамка с поворотом и зеркалом, обрезка областью (разворот или страница); их файлы входят в проверку «пропавших» — отказ до диалога папки со списком, старые файлы целы.

Папка экспорта разбирается чистой `export.PlanDir` (`internal/export/dir.go`; план целей — `export.Plan`, `plan.go`): `ours` — `spread_NN.jpg` прежнего экспорта и `NN.jpg` (две цифры и больше: при ≥ 1000 разворотов `0001.jpg`) с меткой (их заменяем после подтверждения, удаляются только они), `foreign` — `NN.jpg` без метки (кроме `00.jpg`; для частичного экспорта задевают только файлы выбранных целей: `Plan.hitsFile`): экспорт отказывает и ничего не удаляет, чужие фото с таким именем невозможно потерять. Перед диалогом папки `colorReport` считает профили альбома: есть фото `other` — вопрос (`export.ColorWarning`, по умолчанию «Нет»); за ним, тоже до выбора папки, — пустые развороты из плана (`internal/export/blank.go`: `BlankSpreads` по `View` — без фото, текстов, подписей, фона-фото, мест и своего цвета; название не печатается и не мешает), вопрос «Разворот 5 пустой — выгрузить белым?» (не белый фон альбома — «с фоном альбома»), «нет» — экспорт не идёт; `adobe` вопроса не вызывает, пустые места сетки (`View.EmptyPlaces > 0`) — вопрос «На разворотах 3, 7 пустые места (5). В файлы они не попадут, там будет фон. Выгрузить?» (`export.EmptySummaryFor`/`EmptyWarning`, `internal/export/album.go`, больше 10 номеров — «…и ещё K»; после выбора папки, до вопроса о перезаписи), сводка уходит в `export:done` третьим аргументом (`note`) и в лог. Прогресс — события `export:progress`/`export:done`. Флаг «идёт экспорт» ставится до диалога папки; если в папке есть файлы прежнего экспорта (`ours`), спрашивается подтверждение перезаписи. Go помнит папку последнего экспорта, `ShowInExplorer()` открывает её (путь от интерфейса не принимается). `ShowPhotoInExplorer(id)` (`app/reveal.go`; запуск проводника — `internal/osx`) показывает файл фото альбома: путь только из проекта (`Editor.Ref`), `CheckLocalPath`; файла нет — открывается папка, нет и её — ошибка; запуск через подменяемую `revealPath` (= `osx.Reveal`); `ShowInExplorer` зовёт `osx.OpenDir`.

`App` живёт в `internal/app` (в корне только `main.go`: встраивает фронт и `wails.json`, зовёт `app.Run`) и разрезан по файлам: `app.go` (тип, старт), `run.go` (окно Wails и его опции), `api.go` (методы правок), `design.go` (кадр, фон, тексты, подписи; `guardEdit`), `grid.go` (режим «Сетка»), `autosave.go`, `prefs.go` (настройки, «Последние»; логика `config.json` — `internal/prefs`), `media.go` (`/media`, шрифты, сканирование), `files.go`, `export.go` (методы `Export`, `ShowInExplorer`; логика экспорта — `internal/export`), `window.go`, `log.go` (ротация `log.txt` на 2 МБ). Текущий `Editor` лежит в `atomic.Pointer` (`App.editor()`): «Новый»/«Открыть» подменяют его, пока `/media` и автосохранение читают.
