## Раскладка (`internal/layout`)

Фото идут в заданном порядке. Раскладка — дерево: лист — фото, узел — ряд (дети одной высоты) или столбец (дети одной ширины). Для каждого узла высота линейна по ширине: `h = a·w + b`.

- лист: `a = 1/аспект`, `b = 0`;
- столбец: `a = Σaᵢ`, `b = Σbᵢ + gap·(n−1)`;
- ряд: `a = 1/Σ(1/aᵢ)`, `b = a·(Σ(bᵢ/aᵢ) − gap·(n−1))`.

Корень вписывается в область: `h = a·W + b`; если `h > H`, то `h = H`, `w = (H − b)/a`; блок центруется. Фото не обрезаются и не искажаются.

Кандидаты: (1) блок на весь разворот, только при layflat; (2) постраничное семейство: первые k фото слева, остальные справа, по 4 лучших блока на сторону, штраф за разную высоту блоков; (3) bleed — 1–2 фото «в край» с обрезкой не более 30 %. До 7 фото перебираются все деревья (`maxFullTree`), дальше только ряды и столбцы. Предел — `MaxPhotos` = 64 фото на разворот (спека 027); до 16 фото включительно — прежний перебор (эталон `layouts.sha`), с 17 (`ManyFrom`) — быстрые генераторы.

**Ключ** однозначно описывает раскладку: дерево `H(…)`/`V(…)` с позициями фото (сквозными по развороту) — блок на весь разворот, `P[левая|правая]` (страница — дерево, `-`, или с модификатором: `E(i)` — одно фото в край на страницу, `S(…)` — поменьше по центру, `O(…)`/`I(…)` — прижато к внешнему краю / к корешку), `B[full:i]`, `B[right:i]`, `B[pages:i,j]`. Ключ не зависит от размеров: `Build(key, аспекты, Params)` строит ту же раскладку в новой геометрии или отказывает (фото < 1 мм, через корешок без layflat, обрезка > 30 %, неканоническая запись: `P[-|E(i)]` — это `B[right:i]`, `P[E(i)|E(j)]` — это `B[pages:i,j]`). Его хранит проект, по нему `View` считает прямоугольники.

**Перестановки** (`Rearranged`, до 7 фото): раскладки, где фото сидят не в порядке ленты (например, все вертикальные на одной странице). Фото с одинаковыми пропорциями (класс — аспект до 0.001) взаимозаменяемы: перебираются мультимножества классов для левой страницы и все различные последовательности классов на странице (до 5 фото), блок на весь разворот при layflat (до 5 фото), `B[pages:1,0]`. Из дублей по форме остаётся вариант с наименьшим числом инверсий; формы из обычного ряда и тождественные перестановки отбрасываются; в ряд идут не хуже лучшей обычной − 0.03. Перебор ограничен бюджетом 15 000 деревьев. Порядок фото в развороте раскладка не меняет.

**Страницы** (`PageChoices`): для постраничного ключа (`IsPaged`: `P[…]`, а также `B[right:i]` и `B[pages:i,j]`) — варианты одной непустой страницы при неизменной второй (в порядке ленты и с перестановкой), отсортированные по оценке самой страницы. В ряд «в порядке ленты» добавляются модификаторы лучшего блока: у одного фото — в край (обрезка ≤ 30 %), к внешнему краю и к корешку (если сдвиг ≥ 5 % ширины страницы), поменьше (0.65 по стороне); у нескольких — только поменьше. В ряд всего разворота (`Layouts`) модификаторы не идут: автосборка и оценки разворотов прежние.

Оценка: `заполнение − 0.05·log₂(maxS/minS) − штраф за мелкие (< 0.22·H) − штраф за корешок − 0.015·глубина`. Через корешок хорошо идут широкие кадры, узкая полоска фото за корешком штрафуется сильно. Лучшие 24 по оценке (без дублей по ключу) — ряд «в порядке ленты»; `Cached`, `CachedRearranged`, `CachedPages` запоминают результат по аспектам и геометрии.

**Ничьи** (решение 95, 0.10): оценки, равные с точностью `tieEps`, сравниваются квантованными (`tieQ`), а между равными решает ключ — не последние биты и не порядок перебора, поэтому «Авто» и порядок ряда одинаковы на Windows и Mac (FMA на arm64). Так во всех рядах: `Layouts`, `Rearranged`, `PageChoices`, 17–64 фото. Прежний порядок (до 0.10) — `LegacyLayouts`, только для миграции альбомов v ≤ 5 (эталон `legacy.sha` не перезаписывается); ключи первой раскладки сверяет и arm64 — `first16.sha` (≤ 16) и `first.sha` (17–64).

**Многие фото** (17–64, `many.go`, спека 027): перебора нет, деревья строятся генераторами — ряды и столбцы с выравниванием (разрез на ряды — DP по префиксам, r* ± 2 рядов), постранично с разрезом около середины, «крупное первое», при layflat — ряды на весь разворот. Число деревьев ограничено построением, а не временем: «лучшая» не зависит от машины. Ключи — обычные `H(…)`/`V(…)`/`P[…|…]`, `Build` и оценка прежние. Ряд «Авто» — порции по `ManyBatch` = 12 до `ManyCap` = 48: первая — из основных семейств (её первый вариант — лучший, его берут автосборка и `Layout = ""`), следующие — с дополнительными семействами, без повторов ключей; каждое ещё не показанное семейство получает место своим лучшим вариантом. `Layouts(…, limit)` отдаёт первые `limit` элементов, ряд с меньшим limit — префикс большего. Перестановок нет (`BlockMany`), страница из > 16 фото в `PageChoices` — ряды и столбцы этой страницы. Эталон — `testdata/golden/many.sha` (`TestGoldenMany`); группировка `PlanGroups` — `internal/layout/plan/testdata/golden/many.sha` (`TestGoldenPlan600`).

В альбоме длина первого ряда — `model.RowLen(n)`: 24 до 16 фото, 12 с 17. `model.AutoRow` находит наименьшую порцию с текущим ключом (по ней счётчик «Раскладка i / N+» в `SpreadView`: `variants`, `more`), `model.MoreRow` — ряд на порцию длиннее (`MoreLayouts`, плитка «Ещё»). Листание вперёд с последнего варианта досчитывает порцию, если `more`; иначе и назад с первого — по кругу в посчитанном ряду.

**Разнообразие** (`internal/layout/variety`, спека 041): над готовыми рядами `layout` — сам `layout` не менялся (№22); с 051 ряд «Авто» для 3–40 фото строит `variety.Row` (ниже и в `autobuild.md`), эталоны `layouts`, `legacy`, `first16`, `first`, `many` прежние. Ряд «Авто» (051, №36–37) — `variety.Row`: `Row[0]` = `Cached[0]` (лучшая, как раньше), дальше чередуются лучшая по Q ещё не показанной формы из `forms` (Q ≥ Q[0] − допуск; ключ и вид не повторяются) и следующая из `Cached`; длина ≤ `rowLen`, ряд меньшей длины — префикс большей. Формы — пакет `internal/layout/forms` (strip, rows, grid, air, asym, contrast, ladder, frame, figure и др.; `forms.Of` размечает любой ключ по префиксу и геометрии), ключи с `Q/G/L/A/m/U/D` — грамматика `051-layout-variety/c0-grammar.md`. Вид раскладки в `Choice.formName`; подборка делит раскладки на семейства (`Choice.family`): «Плотно», «С главным фото», «Воздух», «В край», «Фигуры» (strip/figure). Лесенка (`ladder`): пол 0.18, полоса [0.25, 1]. Q лесенки: −0.25·s/(h+s) за пустые углы, −0.15 за пустую страницу; в выборе сборки — семейство Figure, направления L/A чередуются (0.13.1, решение №21). Почти одинаковые плитки (та же картинка) сворачиваются в «Похожие» (`twin`). Ничьи генератора `featured` — в квантах (`quanta`, `tieEps` 1e-9), как `tieQ` выше: ничью решает порядок поиска (ряды раньше столбцов), а не последние биты, поэтому результат одинаков на Windows и Mac (№68). Эталоны: `variety/testdata/golden/variety.sha` (выбор сборки по уровням, `TestGoldenVariety`), `featured.sha` (ключи генератора, `TestGoldenFeatured`); оба только amd64, в `release.yml` на arm64 не гоняются (№63). Формы многих фото (072, 17–40 фото со страницами; `forms/many.go`): «Ряды» — `Q[G|G]` с разрезом DP «наименьшая наибольшая сумма пропорций ряда», 2–6 рядов, на страницах поровну или на один больше, разрез страниц у середины ± 2 (вместо `pageRows` №40, он остался для 11–16); «сетка + главное» — главное первым или последним фото страницы высотой в блок из двух рядов, рядом и ниже ряды (планы оцениваются без Build, в Build — 3 лучших; главное по геометрии должно остаться задуманным, иначе раскладка не берётся); «две крупных» — по такому главному на странице. Из вариантов каждого генератора остаются не мельче 0,97 самого крупного (`keepLargest`). Пол главного с 17 фото — доля 0,30 **или** ≥ 3 медиан площади прочих (`manyHeroOK`). «Не мельче мозаики»: `variety.formRelax` = 0,9 мельчайшей стороны `Row[0]` — пол вида снижается до него, но не поднимается (072-8). Бюджет Build на разворот — ≤ 80 до 16 фото, ≤ 200 с 17 (`TestFormsInvariants`); кэши разреза и страниц — в `gen` (Gen зовут параллельно). «Разброс» (105, корень `Z`, лист `n`; `forms.Free`, `forms/free.go`): центр с боками `n` и по плитке на 7 профилей (вниз, вверх, V, Λ, `_/`, `\_`, ровный ряд) на 3–5 фото; в `Gen` не входит, `forms.Of` даёт `Scatter` («Разброс», семья «Фигуры»); в «Других вариантах» идёт первым (центр, плитки в порядке профилей, затем прежний ряд); `Cand.Manual` — `Pick` и `ByFamily` его не берут; эталон `forms/testdata/golden/free.sha`. Скрытые правилом сгиба — `SpreadView.foldHidden` (`forms.FreeFold`).

**Правило сгиба** (спека 064, 0.15; `internal/layout/fold.go`). `Params.FoldAny` (false — «Только широкие», true — «Любые фото»; при `Layflat == false` и у листа не действует) и предикаты `FoldOK1(рамка, аспект кадра, p)` / `FoldOK(rects, asp, p)`: фото, пересекающее корешок дальше `spineEps`, проходит, только если есть `Layflat`, и либо `FoldAny`, либо min(W/H рамки, аспект кадра) ≥ `FoldAspect` = 1,2 и доля ширины с каждой стороны сгиба ≥ `FoldPart` = 20 %. Кадр важен «в край» (рамка шире кадра, сгиб режет середину сюжета; сравнения в квантах `tieQ`). Правило одно для всех путей подбора и стоит в генераторах до отсечения `keep`/`limit` (а не после, иначе в ряду остались бы одни негодные): перебор деревьев `bestBlocksIn` (фильтр `foldOf`), `B[full:i]` в `Layouts`, `manyGen.spread` (17–64 фото, `foldOn`), перестановки `Rearranged`/`Extra`, `forms.admissible`, главное фото (`variety/featured.go`), оценка окна плана (`plan/planfast.go`). `foldOn(p)` = Layflat && !FoldAny && !Sheet: при «Любые» фильтр не вызывается — прежнее поведение бит-в-бит (эталоны `layouts.sha` и др. без перезаписи; «Только широкие» — отдельные `*-wide.sha`). `CacheKey` включает `FoldAny` только там, где он действует. **`Build` правила не знает** — ключ, вне правила стоящий в проекте (свёрстанный раньше), строится по-прежнему; `spreads.SetLayout` пускает такой ключ, если он уже стоит (`foldAllowed`), чужой — только если проходит `FoldOK`. **`LegacyLayouts` без фильтра** (принудительно `FoldAny = true`): он нужен миграции, чтобы прежнее «Авто» не изменилось. Сторож `TestFoldRuleAllPaths`: при «Только широкие» каждый результат всех путей проходит `FoldOK`, при «Нет» ни одно фото не пересекает корешок. Хранение и перенос старых альбомов — `salbum-format.md`.

**Разброс** (спека 105, 0.24; `internal/layout/scatter.go`). Корень `Z(зв…)`: 1–5 фото одной высоты `h = min(10/16·H, (W − (k+1)·air₀)/Σa)` области (`air₀ = max(gap, H/16)`), воздух поровну у краёв и между фото `(W − h·Σa)/(k+1)`, у каждого фото уровень по вертикали `a`…`g` — доля свободной высоты `H − h` (0, ¼, ⅓, ½, ⅔, ¾, 1). Блок занимает всю область, поэтому `O/I/U/D` его не сдвигают (ключ строится, вид как по центру), `S` вписывает в уменьшенную область; высота для оценки — от верха самого высокого до низа самого низкого фото, глубина 1. Лист `n<i>` в корневом `H` — как `m`, только `kappaN` = 0,7 (`node.big`). Подрезка (104) их не трогает: `plainTree` отвергает `Z` и любой `small`. Ряд «Авто» и перебор `Z`/`n` не знают (эталоны `layouts`, `first`, `legacy`, `many`, `shapes` прежние); ключи строят `forms.Free` и ручной выбор (G2). Эталон — `testdata/golden/scatter.sha` (`TestGoldenScatter`, только amd64; после выпуска не перезаписывать). Формат — `salbum-format.md`.

**Подрезка, чтобы закрыть лист** (спека 104, 0.24; `internal/layout/crop.go`). `Params.Crop` — доля по стороне (0…`MaxFitCrop` = 0,15; `fitCrop` зажимает, NaN и ≤ 0 — 0), `Params.Lock` — бит i: у фото i свой кадр (098), его ячейка не подрезается; `Result.Crop` — подрезка блока (наибольшая по страницам). Params остаётся сравнимым (`==`), поэтому бит, а не `[]bool`. Растягиваются только сплошные блоки (`plainTree`: фото без `m`, `H`/`V` из сплошных): `T` без модификатора и страница `P` без модификатора. Воздух (`S/U/D/O/I/E`), `G`, `L/A`, `m`, `Q`, `B[…]` — как раньше. Блок получает общий множитель f пропорций свободных фото; высота блока при ширине w — `(A·w + B1)/f + B0` (`coef`), блок закрывает область (W×H) при `f = (A·W + B1)/(H − B0)`. f вне `[1−t, 1/(1−t)]` или блок уже закрыт (|Δ| < 1e-6 мм) — блок не трогаем, Rects побитно как при `Crop = 0`. Есть фото с Lock — формула не линейна, f ищется делением пополам по ln f (60 шагов; все с Lock — не растягиваем). Правило сгиба проверяется на растянутом блоке (`FoldOK`), нарушивший — нерастянутый. Оценка растянутого `score − CropK·crop`, `CropK` = 1,0. `Build` при `Crop > 0` — `buildCrop` (разбор ключа один раз, прежнее тело `buildParsed` при отказе растяжения). Ряд `Layouts` до `ManyFrom` фото: лучшие `CropPool` = 48 без подрезки → каждая через `Build(p)` → пересортировка: набор не зависит от limit, ряд на 12 — префикс ряда на 24 и 48; с `ManyFrom` порядок прежний (пул 48 там +67 % CPU). `PageChoices` и `CachedPagesInOrder` считают ряды как без подрезки, затем Rects/Score/Crop каждой строки берут из `Build(p)` (порядок прежний); `Rearranged` — `Cached(p)` и `finish` через `Build(p)`. `CacheKey` при `Crop > 0` добавляет `c<Crop>/<Lock>:` (при 0 строка прежняя, Lock без Crop не действует). Эталоны `*.sha` при `Crop = 0` прежние; тесты — `crop_test.go`. План групп (`plan`) считается с `Crop = 0` (так зовёт модель), пулы групп — с подрезкой.
