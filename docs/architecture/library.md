# Библиотека: виды, наборы, каталог, подпись (спека 067)

Подробности и пределы — `docs/specs/0.16/067-library/design.md`; здесь кратко.

- **Виды:** фон (`bg`), стикер (`sticker`), рамочка места (`frame`, 079: папка `Рамочки/`, PNG ≤ 30 МБ и ≤ 4096 px (SVG — через окно, как у стикера; JPEG — отказ), окно проверяется при загрузке и установке набора — нет окна, пропуск с причиной; срез хранится в альбоме, экран — `/media/f/<ID записи>`), разворот (`spread`, шаблон `SpreadTpl` v1). Свои предметы лежат в `library.json`, наборные — в реестре `Наборы/<id>.json` (служебное `base` — граница первой партии для «Новых», 133; `RemovePack` дописывает его оставшимся наборам, читая текущий файл и меняя только это поле, а реестр набора новее программы (`v` > 1), битый или огромный не перезаписывается — 0.28-133-79; вид и стиль стикера Go выводит из имени и размера, в реестре их нет; `zipSize` — размер zip из каталога у наборов из сети и примера (137-31), показывается как размер набора; «Освободится» и квота — по диску); картинки пишутся как `<hex sha256[:8]>.<ext>`, имена из архива путями не становятся.
- **Код ссылки клиента (QR) и миграция признака (0.28-131-157, 215):** `AddQR` ставит записи `qr`; такой стикер в шаблон разворота и макет не берётся (`Store.IsQR`). Коды 0.23–0.27, переименованные фотографом, при `Open` узнаются по строению PNG (`migrateQR`, `qr_migrate.go`: файл ≤ 1 МиБ, квадрат из двух цветов, сетка модулей версии 1…40 с полем, три «глазка» и синхролинии) и получают `qr`; версия миграции — `qrScan` в корне `library.json`, файл правится точечно, реестр новее программы не трогается, повторный `Open` не пишет.
- **Набор** — zip с `manifest.json` (формат 1: id, version, minApp, title, license, `items[{file, kind, theme, name, sha256, size}]`), предметами и необязательным `LICENSE.txt`. Пределы (zip ≤ 300 МБ, записей ≤ 2000, фон ≤ 60 МБ, стикер ≤ 30 МБ, шаблон ≤ 256 КБ, степень сжатия) — design §4.2. Любое нарушение манифеста или архива — отказ целиком; плохой предмет — пропуск с причиной.
- **Каталог** `catalog.json` в репозитории `IliaSA101/sosninaalbums-library` — конверт `{sig, body}` (0.17 №2; отдельного `catalog.json.sig` больше нет): `body` — base64 JSON `{format: 1, seq, packs: [{id, version, minApp, title, about, license, size, sha256, url, counts, needs?, preview?}]}` (`preview` — 144, см. «Образцы наборов в галереях»), `sig` — ed25519 по байтам `body`, base64. `url` — только ассеты релизов этого репозитория; `needs` — id донора дополнения (с 0.27); `seq` растёт с каждой публикацией, программа не принимает каталог с seq меньше принятого (`libraryNet.catalogSeq`).
- **Подпись:** проверка до разбора каталога открытым ключом из программы (`fetch.Keys`: текущий и запасной, сырые 32 байта в base64). Не сходится — обновление отменено; тем же путём (`Client.Parse`) проверяется и сохранённый каталог (ниже, «Сеть»). Закрытый ключ — `docs/private/library-key.pem` (вне git).
- **Ротация ключа:** в программе всегда два открытых ключа. Каталог подписывают текущим; для смены — выпустить версию программы, где запасной стал текущим, добавить новый запасной, затем подписывать новым. Потеряны оба — только новая версия программы.
- **Выпуск набора:** `node scripts/library-pack.mjs packs/<id>` -> `dist/<id>-<version>.zip`, строка в `catalog.json`, подпись (нет файла каталога — отказ, новый каталог только с `--new`; `--seq` больше прежнего); релиз `<id>-v<version>` на GitHub (после «да» владельца). Тестовые наборы и ключ для QA — `scripts/library-testsets.mjs`, `docs/qa/library.md`.

- **Типографии в наборах (123 Б4):** вид `print` — профили `.saprint` ≤ 64 КБ, не больше 16 в наборе и 64 в наборах, minApp набора ≥ 0.26.0 (`library-pack.mjs` проверяет, `counts.print`). Ставит их только набор из подписанного каталога (`Staged.origin` = net); из zip-файла пользователя — пропуск с причиной, набор из одних типографий — «нечего ставить». Разбор — `printprof.Parse` через `Store.SetPrintCheck` при установке и заново при каждой сборке реестра (`ownprint.Service.LibraryChanged` после `emitChanged`); файл — `Типографии/<sha256[:8]>.saprint`, реестр набора хранит `minApp`. Версии: библиотечный перекрывает встроенный при строго большей `version`, из двух наборов — старшая, при равной — установленный раньше; откат — удалить набор.

## Сеть: «Обновить библиотеку», «Скачать», «Скачать все» (067 Ф3, 137)

Спеки — `docs/specs/0.16/067-library.md` (Ф3), `docs/specs/0.29/137-packs-selective.md` и её `design.md`; решения 0.17 №2–4, 0.29-137-\*. Здесь — как сделано в коде.

**Где код.** Единственный сетевой клиент — `internal/decor/fetch` (https, белый список хостов `GitHubHosts`, параметры адреса — только CDN после 302, подпись до разбора, архив по размеру и sha256 из подписанной строки). Служба — `internal/app/libpacks`: `net.go` — входы, согласие, отмена, проверка при запуске; `batch.go` — одна дорога всех операций, план, цикл установки, виды ошибок; `pick.go` — строки «Можно скачать» и состав «Скачать»; `cache.go` — сохранённый каталог. Методы App — `internal/app/packs.go`; окно — `frontend/src/shell/packs/` (`PacksAvail.svelte`, `packavail.ts`, `packnet.ts`, `packnet.svelte.ts`).

**Согласие и состояние** — `config.json` → `libraryNet` (`prefs.LibraryNet`): `allowed`, `atStart` (без согласия не действует), `checked` (unix мс последней проверки обновлений), `catalogSeq` (наибольший принятый seq: меньший каталог отвергается как подпись), `skip` (удалённые вами, ≤ 500), `announced` (id наборов, о которых пользователю уже сообщили: «новые» считаются от него, а не от сохранённого каталога; пишет только ход наборов, ролики его не двигают; нет поля — состав сохранённого каталога, 0.30-140-24). Без `allowed` любая операция — `ErrNoConsent` без единого запроса; согласие сверяется ещё раз после регистрации отмены (`beginNet`), отзыв (`SetLibraryNet(false, …)`) снимает флажок и обрывает идущий ход. Одна операция наборов за раз (`ErrBusy`), библиотека «только чтение» — `decor.ErrReadOnly` до сети.

**Операции** (все идут через `libpacks.update`, итог — `LibraryUpdate`):

| Кнопка                | Метод App                 | Что ставит                                                                                                                                                                                                                                                                                | `checked` |
| --------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| «Обновить библиотеку» | `UpdateLibrary()`         | только стоящее: новые версии стоящих наборов и недостающие дополнения к стоящему донору (`updateWant`). Новые наборы не ставит — они в разделе «Можно скачать»                                                                                                                            | пишет     |
| «Скачать» в строке    | `DownloadLibraryPack(id)` | состав строки по **свежему** каталогу (`closure`): набор, его нестоящие доноры вверх по `needs`, годные дополнения вниз. id не по грамматике — `ErrGone` до сети; id нет в свежем каталоге — `ErrGone` «набора больше нет в списке — список обновлён» (сохранённый каталог уже переписан) | не пишет  |
| «Скачать все (N, M)»  | `DownloadAllLibrary()`    | ровно строки раздела, которые видел пользователь: сохранённый каталог **до** операции без серых и «удалён вами», их составы — по свежему каталогу                                                                                                                                         | пишет     |
| проверка при запуске  | — (`StartCheck`)          | как «Обновить»; всё вместе больше `startOffer` (100 МБ) — не ставит, а предлагает                                                                                                                                                                                                         | пишет     |

Порядок `update`: прежний сохранённый каталог (`prev` — объявленное `announced`, а без него состав каталога; id для «новых», `shown` — строки для «Скачать все») → `Client.Catalog` → отсев id-устройств (`con`, `nul`… → `Skipped`) → запись `catalogSeq` → сохранение каталога → план (`planOf` → `netPlan`: версии, причины «из файла» / «встроенный» / «нужна новая программа» только у стоящих, донор раньше дополнения) → цикл установки. В конце (и при обрыве тоже) — снятие пометок «удалён вами», `Relink` и **одно** `library:changed`, если что-то встало; затем итоги `available` и `fresh`, у «Скачать» — `picked` и `why`. Ошибка каталога (сеть, подпись, seq, формат новее) — до установки, библиотека прежняя.

**Сохранённый каталог** `library-catalog.json` в папке настроек (у стенда — своя папка): конверт `{sig, body}` последнего удачного `Catalog` байт в байт. Окно «Наборы» строит раздел только из него — сеть при открытии окна не трогается. Файл недоверенный: `paths.CheckLocalPath`, `os.Lstat` — только обычный файл ≤ `fetch.MaxEnvelope` (1,4 МБ), `library.OpenLocal` и `os.SameFile` с проверенным, затем `Client.Parse` (подпись и seq не меньше `catalogSeq`, без записи seq). Нет файла — молча (первый запуск 0.29); не читается — одна строка в log.txt за сеанс, раздел пуст, проверка при запуске «новыми» ничего не объявляет. Читается один раз за сеанс (окно опрашивает список раз в 2 с), неудача тоже запоминается. Запись — `library.WriteFileAtomicMode` (0600, временный файл и переименование; прежние `library-catalog.json.*.tmp` убираются), ошибка записи — только log.txt. Дата «по списку от ДД.ММ» — `PackList.availAt`: время файла (после записи — его `ModTime`, не записался — «сейчас»); 0 — списка нет, вместо раздела «Наборы из интернета появятся здесь после «Обновить библиотеку»». Адрес архива «Скачать» берёт только из свежего каталога, поэтому худшее при подмене файла — пустой раздел.

**Строки «Можно скачать»** (`availRows`, по порядку каталога): набор, которого нет в библиотеке (стоящий любого происхождения, встроенный тоже, строки не имеет). Дополнение к нестоящему донору своей строки не имеет — его ставит «Скачать» донора («вместе с: «…»»); дополнение к стоящему донору — строка «дополнение к «…»». `bytes` и `addonTitles` — состав `closure` (вниз не идут стоящие, помеченные «удалён вами» — кроме нажатого, и требующие программу новее). `why` непусто (`minApp` новее программы) — «Скачать» серая с причиной; `removed` — пометка «удалён вами». `PackList.all` {count, bytes} и `LibraryUpdate.available` считает одна функция `shownPlan` — подпись «Скачать все» и действие совпадают. `fresh` — строки без `why` и без «удалён вами», которых не было в `prev`; в тексте итога только у «Скачать все» («появились новые: N — список обновлён»).

**Продолжение хода и обрыв** (`installAll`, `fatalNet`, `repeatKind`): набор, который не встал, идёт в `LibraryUpdate.failed` (название и причина, `failWhy`: битому — «скачался с ошибкой, повторите»), ход идёт дальше. По набору: 404 одного ассета, «библиотека заполнена» (`decor.ErrLibFull`, квота 2 ГБ проверяется до скачивания каждого набора — следующий меньший может влезть), недопустимый id (`decor.ErrBadPackID`), битый zip, «архив не совпадает со списком наборов», «нечего ставить». Дополнение, чей донор в этом ходе не встал, пропускается без строки в `failed` (log.txt; у «Скачать» — причина в `why`). Обрывают весь ход сразу (`fatalNet`): отмена и выход программы, отзыв согласия, `ErrTLS`, `ErrAddress`, ответ не 200 кроме 404 (429, 403, 407, 5xx), `fetch.ErrDisk` — только от записи на диск, `fetch.ErrSlow`. Обрывает **вторая подряд** неудача того же вида (`repeatKind`): «связь» — `ErrOffline` и застой `ErrTimeout`; «битый» — `ErrBroken`; «подряд» — без удачи и без неудачи другого вида между ними. При обрыве метод возвращает ошибку (тост ошибки, итога нет), поставленное до неё остаётся, `library:changed` уже пришло, `checked` не пишется. Поштучные неудачи `checked` пишут: иначе испорченный у издателя архив качался бы при каждом запуске. «Отменить» во время установки: набор доустанавливается, следующий не начинается; `.dl-<id>.tmp` удаляется всегда.

**Предел времени** на архив — `fetch.PackLimit(size)` = max(15 мин, size / 64 КиБ/с): 70 МиБ — 1120 с, `MaxZip` (300 МиБ) — 80 мин. Застой 30 с — отдельно (ловит оборванную связь). Не уложился — `*SlowError` (`errors.Is(err, ErrSlow)`), текст «Связь слишком медленная: «X» не скачался за 19 мин», ход обрывается: следующий набор упрётся так же.

**«Удалён вами»** (`libraryNet.skip`): ставит `RemovePack` только набору из сети. «Обновить» и «Скачать все» помеченных не ставят. «Скачать» идёт мимо пометки для нажатого id и доноров вверх (`force`) и снимает её **после удачной установки** (отказ сети, пропавший набор, битый архив пометку не стирают); помеченное дополнение «Скачать» донора не возвращает. «Добавить из файла» снимает пометку своего id. «Вернуть» (`ResetLibrarySkip`) снимает все: строки теряют «удалён вами», «Скачать все» снова их ставит.

**Проверка при запуске** (`ScheduleCheck` из `OnDomReady`): только с `allowed` и `atStart`, не чаще 20 ч по `checked` (часы ушли назад — тоже пора), раз за сеанс, через 15 с. Ставит тихо то же, что «Обновить»; больше `startOffer` — только предложение. Одно событие `library:start` {updated, offer, fresh} (если хоть одна часть не нулевая) — один тост: «Обновлено наборов: N; есть обновления наборов: N (M МБ); есть новые наборы: N (M МБ)», кнопка «Скачать» (есть `offer` — зовёт `UpdateLibrary`) или «Показать» (окно «Наборы», прокрутка к разделу). Новые объявляются один раз: следующий раз они уже в `prev`. Неудачи, «только чтение» и занятость — только log.txt (при двух последних `checked` не пишется).

**Удаление донора:** `PlanRemovePack(id).addons` — названия стоящих дополнений id по сохранённому каталогу; вопрос «Удалить набор?» добавляет «Дополнения к нему — «…» — останутся, но их новые версии приходить перестанут, пока набор не скачаете снова». Нет каталога — прежний текст.

## Образцы наборов в галереях (спека 144, 0.31)

Плитки «⤓ набор, размер» нескачанных наборов в «Фонах», «Стикерах», «Рамочках», «Развороты» и «Макеты альбома»; щелчок скачивает набор и ставит выбранное. Техрешение — `docs/specs/0.31/144-gallery-pack-tiles/design.md`, разбор безопасности — `security.md` рядом, решения — `0.31-144-*`. `.salbum`, `View`, undo не затронуты (скачивание — не правка, постановка — прежний шаг).

- **Каталог:** необязательное поле `preview` строки — `{url, sha256, size, w, h, rows[{kind, w, h, items}]}`: один JPEG-лист ≤ 384 КиБ с клетками предметов; `items` — `sha256[:16]` записей манифеста. Формат каталога остаётся 1: старые версии поле пропускают. Разбор отдельный и построчный (`fetch/preview.go`): сырое поле ≤ 8 КиБ до `Unmarshal`, пределы лист/ряды/клетки; негодное поле — строка без `preview` и причина в `Skipped`, каталог цел. Лист делает издатель (`library-verify -sprite <zip>`) и вносит `library-pack.mjs --sheets` (старые наборы без переупаковки — `--preview-only`).
- **Кэш листов** `<cfgDir>/library-previews/<sha256>.jpg` (`libpacks/preview.go`): нет папки настроек (пуста или не абсолютна) или папка листов не обычная папка — образцы выключены на сеанс. Файл недоверенный: при каждом чтении обычный файл, размер, `OpenLocal` + `SameFile`, sha256; не сошлось — файл удаляется. Уборка `gcPreviews` после `remember` в `Fresh` — только свои имена (64 hex + `.jpg`), которых нет в действующем списке, и не во время задания; `.dl-*.tmp` — в начале задания.
- **Задание докачки** `FetchPreviews` (`libpacks/prevjob.go`; окно зовёт `App.FetchPackPreviews` → `StartPreviews` → `GoBG`): только с согласием, списком и не «только чтение»; свой замок `prevMu`, замок наборов не берёт. Качает по одному недостающие листы тех строк, что дали бы плитки, до 50 за задание, каждый — своей обёрткой `fetchSheet` (временный файл, `Client.Download`, 60 с, `Rename`). Отзыв согласия (`SetNet(false)`) обрывает задание через `stopPreviews`; «Отменить» окна «Наборы» — нет. Неудача связи или диска — пауза 10 мин (`prevPause`); 404 и не тот размер/sha — лист в `bad` задания до конца сеанса; два `ErrBroken` подряд в одном задании — это связь: пауза, второй в `bad` не кладётся. Итог — событие `library:previews` (`events.md`).
- **Клетки** (`libpacks/cells.go`): лист разбирает только Go — `DecodeConfig` и сверка с `w×h`, ≤ 4 Мп, обход маркеров до SOS (≤ 64), только baseline (SOF0/SOF1) YCbCr или Gray, затем `jpeg.Decode`, нарезка и перекодирование q90; WebView получает перекодированные клетки. LRU 8 МБ по ключу sha256 + раскладка, один разбор за раз (слот-канал с отменой по запросу), под слотом второй взгляд в LRU: 24 плитки листа — один разбор. Лист с клетками > 2 МБ или отвергнутый — в `cellBad` до роста seq списка (0.31-144-41), `Tiles` его пропускает.
- **Адрес** `/media/lp/<id>/<kind>/<i>?v=<sha256[:8]>` (`libpacks/serve.go`, `app/packs_tiles.go`, ветка `App.media` до `/media/f/`, `/media/o/`): только GET/HEAD (иначе 405), хвост ровно из трёх сегментов, `fetch.ValidID`, не имя устройства, вид из пяти, индекс без знака и нулей, набор не стоит в библиотеке, согласие есть; прочее — 404. Строка и `preview` — только из сохранённого списка, сети и путей из адреса нет; `?v=` не читается. Ответ — `image/jpeg`, `nosniff`, `Cache-Control: no-cache`, `Content-Length`, без `ServeContent` (304 не бывает: Wails на WebView2 превращает его в 500); `recover` → 404. Согласие для раздачи — из памяти службы (`consent.go`, обновляет `SetNet`; 0.31-144-42).

## Типографии (123 Б1): граница доверия

Профиль типографии — данные, но они задают пределы, имена файлов выгрузки и адрес кнопки, поэтому читаются как чужие (design `123-print-profiles/design.md` §6).

- **Файл `.saprint`** (ввод «Добавить из файла…», путь от пользователя): `paths.CheckLocalPath` и `library.OpenLocal` (проверенная цель, сверка с открытым — без подмены ссылки), только обычный файл (FIFO не вешает импорт), предел 64 КБ + 1 до чтения, затем строгий `printprof.Parse` — один JSON-объект без хвоста, неизвестные поля и повтор ключей — отказ, все числа конечные и в пределах `ClampSettings`/`ClampCoverSpec`, строки UTF-8 без управляющих и форматирующих знаков (bidi, нулевая ширина), адрес только `https://` с ASCII-хостом (последняя метка — буквы или `xn--`, не число и не `localhost`) без `user@`, порта кроме 443 и знаков, которые Wails `BrowserOpenURL` не откроет, все адреса профиля на одном сайте (`www.` не в счёт), названия без смеси алфавитов в слове и сравнение двойников по скелету `printprof.NameKey` (0.26-123-47…49), префикс имён `^[0-9A-Za-z_-]{0,8}$`. Любой отказ — ошибка с причиной без пути и без записи.
- **Чужой id не перекрывает чужое:** встроенный, библиотечный и без `own-` id при импорте превращаются в копию под новым `own-<hex>`; пространство `own-…` принадлежит только своим, `Compose` пропускает такое из набора каталога.
- **Подпись проверяется один раз — при установке набора.** Папка данных (`Библиотека/`, реестр наборов, `origin`, `Типографии/`) дальше считается доверенной: кто может писать туда, может и подменить программу. Файлы своих типографий при каждом запуске разбираются тем же `Parse` (битый — пропуск со строкой в log.txt), но подписи не проверяют. Типографии из набора каталога (Б4, вид `print`) принимаются только из подписанного каталога, не из «Загрузить своё».

## Публикация набора (129 Т10)

Порядок, без перестановок:

1. Рецепт набора (`recipe-<id>.json`, вне git).
2. `packprep` по рецепту: нарезка, вырезы, удаление фона.
3. `node scripts/library-pack.mjs packs/<id>` с `--seq` больше прежнего (каталог подписывается ключом оркестратора).
4. `library-verify` — проверка архива и каталога (подпись, sha256, пределы).
5. Лист предпросмотра (`preview-<id>.png`): владелец смотрел первые наборы глазами до выпуска.
   - Лист образцов (144): `library-verify -sprite <zip> -out <папка>` от собранного архива (клетки только из его байтов), лист смотреть глазами; в строку каталога он идёт через `library-pack.mjs … --sheets <папка>` (вышедшие наборы без переупаковки — `--preview-only <id>=<zip>`, один прогон — один `seq`); ассет `<id>-<версия>-preview.jpg` — в тот же релиз.
6. `gh release create <id>-v<версия>` с архивом.
7. Только после релиза — коммит каталога и push репозитория наборов.
8. Скачать архив по `url` из каталога и сверить sha256.

Правила:

- **Новые наборы после 137 (вторая волна, 0.30; решение 0.29-137-27):** `minApp` не ниже первой версии с 137 (0.29.0). Клиенты 0.17–0.28 ставят весь каталог и по тосту «Есть новые наборы: 20 (1,6 ГБ) · Скачать» заполнили бы библиотеку первыми по списку, упираясь в 2 ГБ; с `minApp` 0.29.0 они такие строки пропускают (как дополнения с `minApp` 0.27.0 — 0.27-129-12). `MAX_ZIP` (70 МБ — бюджет старых клиентов: предел 15 мин) поднимать только для строк с таким `minApp`: у 0.29+ предел растёт с размером (`PackLimit`). Проверка — в `scripts/library-pack.mjs` (0.30-wave2-1): id, которого нет в `--catalog` (готовый каталог; первый набор нового каталога с `--new` — не в счёт), с `minApp` ниже 0.29.0 — отказ до записи с причиной; повторный выпуск набора, уже стоящего в каталоге, — прежнее правило (`--prev`). Предел zip: `MAX_ZIP` 70 МБ для `minApp` ниже 0.29.0, `MAX_ZIP_WAVE2` 240 МБ для 0.29.0 и выше (жёсткий предел клиента `fetch.MaxZip` = `pack.MaxZip` 300 МБ, `PackLimit` 240 МБ — 3840 с при 64 КиБ/с; запас 60 МБ). `readZip` инструмента режет распакованное целиком на 1 ГБ (как `pack.MaxTotal`). Стенд QA в разработке 0.29 читает версию из `wails.json` (0.28.0, пока её не подняли), поэтому строки с `minApp` 0.29.0 на нём серые.
- **v1 заморожен:** в версию можно добавлять, убирать предметы нельзя (у пользователей они уже в альбомах). Недостающее — дополнительным набором с `needs` (зависимость от основного).
- **Рамки по 9 срезам — только с орнаментом в углах.** Опыт свадьбы: рамки без него «тянутся» на 77–95 % площади и исключены.
- **Места разворотов — точно 3:2 / 2:3**, иначе срез рамки и фото расходятся.
- **Ключ подписи — только у оркестратора:** исполнитель его не получает и каталог не подписывает; релиз, push и `--seq` — после «да» владельца.
