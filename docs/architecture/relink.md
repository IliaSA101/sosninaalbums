## Перепривязка недостающих фото

Если файла фото или папки нет ни по основному пути, ни по `abs` (проект перенесли на другой компьютер или диск), фото остаётся в проекте. `App.rescan` после каждого сканирования считает `library.MissingOf` и шлёт событие `missing` (ID фото без файла; тот же список — `State.Missing`). Чинят `SuggestDrive` (только чтение: по самой частой пропавшей букве диска ищет, на какой из остальных дисков файлы переехали), `RelinkDrive(from, to)` (смена буквы у пропавшего), `RelinkFolder`/`RelinkFolderPath` (поиск в папке по имени и размеру файла; найденное в нескольких равноценных местах не привязывается). `refreshMissing` считает недостающие в фоне (`bg.Go`) с поколением `missGen`: отчёт устаревшего поколения отбрасывается, событие `missing` уходит под `emitMu`; том, не отвечающий по `osx.Reachable`, считается пропавшим без обращения к файлам. `/media/*` для фото из `missing` (и с мёртвого тома) отвечает 404, не читая файл. Старт на мёртвом томе последнего альбома (`loadStartup`) открывает черновик с тостом «Диск Z: … недоступен», `LastProject` не меняется. Проект, не принятый `NewEditor` при запуске (`startEditor`), — пустой альбом, уведомление и `draftLocked` (черновик не затирается). Всё — одна правка `Editor` (undo, затем `salbum.Rekey`); ссылки-символы на нелокальные цели при поиске и сканировании пропускаются (`library.statLink`).
