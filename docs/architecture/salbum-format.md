`Load` (`Decode`, паника разбора под `recover` → «файл проекта повреждён»): отвергает файл > 50 МБ, больше `MaxSpreads` = 1000 разворотов («слишком много разворотов»), `null`-разворот, нелокальные и битые пути (`paths.CheckLocalPath`: на Windows белый список `X:\…`, всё остальное — UNC, `\??\`, `\?\` — отказ; относительный путь проверяет `CheckRel`). Если альбом открыт с UNC, относительный путь не разрешить: берётся `abs`, без него — отказ. Путь фото: основной, если файл есть и `size` совпал (или неизвестен) → `abs` → основной с другим размером (W/H из заголовка) → нигде: основной, а `abs` остаётся в `Alt`/`FolderAlt` и пишется обратно как был. Папки (`loadFolders`): повторы схлопываются, не больше `MaxFolders` = 10 000 (хвост сверх 2×предела не разбирается). Отметки (`decodeMarks`, `marks.go`) вторичны — битая запись отбрасывается, а не весь файл (строка в log.txt): путь через `candidates`/`CheckLocalPath` (длиннее `paths.MaxPathLen` = 32 767 — отказ), выбор основной/`abs` — по наличию папки, а не файла (stat на ≤ 1000 папок, не на тысячи фото; файл не найден — отметка остаётся, иначе автосохранение стёрло бы отбор при неподключённом диске); не нашлось ни там, ни там — основной путь, `abs` хранится в `Mark.alt` и пишется обратно как был; поле вне допустимых значений — `nil`, запись без полей — прочь; повтор ID — остаётся найденная по основному пути, среди равных — первая; сверх `MaxMarks` = 100 000 уходят сначала отметки вне папок проекта (`underAny`, O(log папок)), затем последние в файле. `decodeFile` кладёт отметки в неэкспортируемое `Project.loaded`, `NewEditor` копирует их в `Editor.marks`; проект в Editor — своя копия через JSON (`own`), пути перепроверяет `salbum.Check` (`CheckLocalPath` папок, `FolderAlt`, фото и `Alt`, своих отметок; без диска и лимитов), отказ — ошибка; `Save`/`WriteCopy` пишут `e.marks`. `MaxTexts`, `MaxPlaces`, `MaxMarks` и `MaxFolders` `Load` чинит с потерей — поднимать их только с новой версией формата. Фото через корешок (спека 064, v11, общий на 0.15). `settings.foldAny` — при `layflat` через корешок идут любые фото (`true`) или только широкие (`false`, правило `layout.FoldOK`); положение настройки: `!layflat` — «Нет», `layflat && !foldAny` — «Только широкие», `layflat && foldAny` — «Любые фото». Поле пишется всегда (без `omitempty`); `ClampSettings` обнуляет его без `layflat` и у листа. Новый альбом — `layflat: true, foldAny: false` («Только широкие»). Чтение файла до v11 (`salbum/fix.go`): `foldLegacy` на время чтения ставит `foldAny = true` у файла с `layflat` (так «Авто» и ничьи до v6 считаются по прежнему поведению, без правила сгиба), последним шагом `migrate` вызывается `pinFoldAuto`: `foldAny` снимается (альбом становится «Только широкие»), а у каждого разворота с «Авто» (не сетка, есть фото), где первая раскладка по новому правилу другая, в `layout` закрепляется ключ прежней первой (`pinKey`: сравниваются `layout.Cached` при прежних и нынешних `Params`); негодный ключ тоже заменяется. Ключ вне правила остаётся рабочим: `Build` правила не знает, `SetLayout` пускает уже стоящий ключ (`spreads.foldAllowed`). Файл с `layflat: false` — «Нет»; без поля `layflat` — «Только широкие» (умолчание `DefaultSettings`). Ряды закрепления считаются параллельно (`eachSpread`), как `migRows`. Тесты — `salbum/roundtrip/fold_test.go` (`TestLoadV10FoldWide`, `TestLoadV10FoldNone`, `TestLoadNoLayflatField`, `TestLoadV5FoldLegacy`, `TestSaveFoldV11`).

Разметка разворотов и обрез (спека 066, v11, `omitempty` — файл без них байт-в-байт прежний). `settings.bleed` — обрез (вылет) по внешним краям разворота, мм: только полоса на холсте при «Вид ▸ Безопасная зона», геометрия, экспорт и автосборка не меняются; `ClampSettings`: 0…min(10, четверть меньшей стороны), NaN/Inf → 0. `spreadGuide` — файл-разметка разворотов (один на все развороты и листы 031), хранится в `Project`, а не в `settings` (путь из интерфейса не принимается — как `cover.guide`), с запасным абсолютным `spreadGuideAbs`; грузится, пишется и перепривязывается теми же `loadGuide`/`encodeGuide`/`relinkGuide`, что у обложки (`salbum/cover.go`), `Check` проверяет оба пути («разметка разворотов»). Разметка — `.psd`, `.jpg`, `.jpeg`, `.png` (`guideExt`); `.psd` бывает и у `cover.guide`. `.psb` — отказ при выборе с текстом «сохраните его как PSD» (`CheckGuide`, `psd.ErrPSB`). Из PSD читаются только заголовок, направляющие и сведённое изображение (`internal/library/psd`, без слоёв), в файл альбома попадает лишь путь.

Фото корешка (спека 061, v10, `omitempty` — файл без него байт-в-байт прежний). У листа обложки `bgPhotoS` — фото фона области `spine`: корешок с обоими расставами и заворотом, `[X2, X5] × [0, H]` (`AreaOf`; области задней и лицевой прежние, на расставах перекрываются с ним). Тот же `Backdrop`, что у `bgPhoto*`: рамка, `rot`, кадр с наклоном, зеркало, `fade`; предел рамки — 3 большие стороны корешка по обеим осям («Поворот» 90° не сжимает рамку), нижний — ширина корешка, если она меньше 10 мм. Бывает только у обложки в раскладке `both` («Задняя + корешок + лицевая»): `Load` снимает его у разворотов и у обложки в `""`/`wrap` со строкой в log.txt (`clampBackdrops`), `bgPhoto` (одно фото через лист) снимает `bgPhotoL/R` и `bgPhotoS`. Отдельные фото (спека 097, v16, общий на 0.22; `omitempty` — файл без отдельных фото байт-в-байт прежний, кроме номера). `loose` — список добавлений `{id, at, files}` в порядке добавления; `id` — 12 hex (`model.NewID`), `at` — время добавления в Unix-секундах (число: читается и дробное, и «1e9», зажим в [0, 9999 год]), `files` — записи как у `folders` (`path` относительный от альбома или абсолютный и запасной `abs`) в порядке выбора. Отдельные фото — источник фото ленты рядом с папками (`Project.Loose`, `LooseFiles()`), их отметки и подборки живут в `marks` по пути, как у фото папок. Пределы: `model.MaxLooseAdds` = 500 добавлений, `MaxLooseFiles` = 2000 файлов на проект; из сырого списка до разбора берётся не больше 2·предел (stat на каждый файл не растёт от чужого файла). `Load` (`salbum/loose.go`, `loadLoose`): битая запись — плохой путь, имя устройства Windows, не JPEG/PNG — пропускается, вся остальная часть добавления остаётся, итог — одна строка в log.txt без путей (097-4: добавления не держат вёрстку, отказ открыть альбом хуже); негодный или повторный `id` заменяется новым; основного пути нет, а запасной есть — берётся запасной, нет нигде — путь и `Alt` остаются и пишутся обратно. Сразу после `loadFolders`/`loadLoose` на проекте любой версии идёт `Project.FoldSources(paths.Linked)` (093-4): повтор папки и папка внутри другой папки списка уходят, отдельное фото внутри папки списка уходит, повтор пути — позднейший, пустое добавление — целиком, хвост сверх пределов режется; «внутри» — куда дойдёт обход сканера (`paths.Reaches`): подпапка на «.», с именем устройства или за ссылкой/junction остаётся отдельным корнем (сканер туда не заходит — свёртка потеряла бы фото). Проверка ссылок (`paths.Linked`, Lstat) — функция, которую вызывающий передаёт в `FoldSources` (модель без IO), и только у вложенных кандидатов. v15 → v16: `migrateV16` (`salbum/fix.go`) пока пустая, место для шагов 0.22; v15 открывается без отдельных фото, первая запись делает `.v15.bak`; 0.21 файл v16 не откроет (`ErrNewer`) и не затрёт отдельные фото автосохранением.
