## Отправить по ссылке (146)

Спека — `docs/specs/0.32/146-flipbook-upload.md`, техрешение — `146-flipbook-upload/design.md`, развилки — `decisions.md` `0.32-146-*`, разбор безопасности — `146-flipbook-upload/security-review.md`. Здесь — устройство по коду; номера решений вместо пересказа.

Назначение: «Файл ▸ Отправить по ссылке…» отдаёт альбом сервису листалок (`sosninaalbums-cloud`, другой репозиторий) и возвращает ссылку (и пароль) для клиента. Программа готовит страницы и говорит с сервисом по открытому контракту `/v1` (модуль `api/albums`, отдельный `go.mod`: клиент `albums.Client`, типы, `v1/openapi.yaml`, поддельный сервер `albumstest` и `cmd/albums-fake` только для тестов и стенда, в exe не входят). Альбом, `.salbum`, `View`, undo и `rev` выгрузка не меняет (как экспорт, 0.32-146-9); сеть — только по действию фотографа: «Подключить», «Выгрузить», «Обновить», «Продолжить», «Изменить», «Продлить», «Отозвать» (design §6 п. 7). Открытие окна (`ShareState`) сети не трогает.

### Слои

- `internal/app/share.go` — фасад: методы `App` и DTO (`ShareOptions`, `ShareChange` — определённые типы от `sharer.Options`/`Change`; `ShareView`, `ShareService`, `ShareAlbum`, `ShareLink` написаны заново, пары — `TestDTOPairs`), `Host` службы (`shareHost`), `pinShare`. `sharejob.go` — снимок альбома `share.Job` (`shareJob`).
- `internal/app/sharer` — служба `Service` (проверки, вопросы, фон, загрузка, правки, отзыв). Проекта не видит: от альбома получает только `share.Job` (0.32-146-T4-1, depguard); остальное — поля `Host` (позднее связывание над `App`).
- `internal/share` — чистая логика: хэш сцены, манифест из страниц, состояние ссылки, «Придумать», текст для клиента, адрес сервиса. `internal/secret` — токен. `internal/prefs` — `shares.json`, `config.json → share`. `internal/export/web.go` — страницы книги.
- Окно — `frontend/src/shell/share/` (только рисует; строки хода, срока и ссылки готовит Go).

### Поток «Выгрузить» (`Service.Share`, `start.go`, `upload.go`)

1. **Флаг** `begin`: идёт экспорт — «Сейчас идёт экспорт — дождитесь его конца» (и наоборот: `export.go` смотрит `shr.Busy`, 0.32-146-18); идёт выгрузка — «Выгрузка уже идёт», у другого альбома — «Идёт выгрузка другого альбома…» (0.32-146-29); идёт правка ссылки — отказ. Флаг стоит с начала вопросов: пока диалог открыт, второй вызов не пройдёт.
2. **Снимок** `Host.Plan` (`shareJob`, один `Editor.SnapshotAt` под замком): путь, отпечаток, печать, страницы (`export.NewWebSpec` — 1600 px по длинной стороне, JPEG q82, 0.32-146-3), хэш сцены, оценка размера. Отказы окна (`Job.Block`): не сохранён (с «Сохранить…»), лист виньетки, нет разворотов (0.32-146-14, T5-7). Отказы выгрузки (`Job.Refuse`): пропавшие фото и рамки (`export.MissingPhotos`, как экспорт). Дальше служба «текущий альбом» не спрашивает: путь, сцена и страницы одного хода — от одного снимка (В1). Нужны подключение и токен (`need`).
3. **Запись и срок.** Запись пути берётся с проверкой отпечатка (см. «Записи»); `options` собирает название, пароль, срок: у новой ссылки срок обязателен (30, 90 или 365 дней), `Days == 0` годится только продолжению и обновлению (0.32-146-T4-4, T5-6). `askLink`: запись другого сервиса, «нет на сервере» или с истёкшим сроком — только новой ссылкой и после вопроса; запись другого проекта на этом пути — тоже вопрос (`foreignQuestion`); записи нет — без вопроса (0.32-146-T5-8).
4. **Вопросы** `Job.Questions` — как у экспорта, кроме пустых разворотов и папок: профиль цвета, пустые поля и имена, шрифты, заготовки (0.32-146-17). «Нет» — ничего не отправлено и не создано, `Share` возвращает `false, nil`.
5. **Отпечаток в файл** `Host.Pin` (`pinShare`) — до первой записи о ссылке. Временная папка `<кэш>/<папка программы>/share/up-*`, 0700 (`tempDir`; нет абсолютного кэша — отказ, С5). Фон — `GoBG`; `Share` возвращает `true`.
6. **Фон** `runShare`: предел памяти снят на время рендера (`LiftMemory`); `execute`: `Health` (пределы сервиса; страниц больше — отказ) → `export.RunWeb` во временную папку → `share.BuildManifest` (sha256, байты и px — из самих файлов, пределы до чтения) → `open` → `upload` → `publish` → проверка ссылки → `adjust` → запись.
   - `open`: записи нет — `Create` (срок и пароль рядом с манифестом, не в нём, 0.32-146-7); запись есть — `Update` (новая редакция, ссылка та же, прежняя версия видна клиенту до `publish`). 404 на `Update` — запись «нет на сервере» и вопрос, после «Да» — `Create`. Запись с `id` ложится сразу после `Create` (до загрузки).
   - `upload`: `missing` от сервиса (подмножество небелых страниц манифеста, иначе «Сервис ответил непонятно», 0.32-146-T1-4) — 3 потока, на страницу до 3 повторов (0.32-146-16): сеть и 5xx — паузы 2/4/8 с, 429 — `Retry-After`, но не больше 60 с; 401, 404, 409 `hash_mismatch`, 413 — без повтора. Первая ошибка останавливает остальные потоки.
   - `publish`: 409 `pages_missing` — догрузка названных страниц один раз и повтор. Ссылка из ответа проходит `printprof.CheckURL` (на стенде — ещё loopback, 0.32-146-25), иначе запись не пишется.
   - `adjust`: `Patch` только если срок или пароль отличаются от сервисных; смена пароля всегда с `revoke_sessions` (0.32-146-T4-5).
   - Запись `url`, срок, пароль, `scene`, время — одной `putIf`.
7. **Конец:** временная папка удаляется (успех, ошибка, остановка); 401 — токен убран, записи целы (`tokenLost`); 404 — запись «нет на сервере» (`markGone`); флаг снят; `share:done`. При запуске программы `sharer.CleanTemp` убирает `up-*` старше суток (по `Lstat`, ссылки и чужие имена не трогает).

Ход (события, 0.32-146-T4-3): `share:progress {phase, done, total, bytes, totalBytes}` — `pages` (рендер: считаются листы — обложка и развороты, не страницы), `upload` (страницы и байты, не чаще 10 раз в секунду, последнее всегда), `publish`; `share:done {err, stopped}`. Окно можно закрыть, выгрузка идёт; при открытии `ShareState` даёт `busy` и окно показывает ход.

### «Обновить по ссылке»

Состояние `changed`: сцена (хэш входа рендера) не равна записанной. Тот же `Share` с `Days == 0`: название, пароль и срок берутся из записи (0.32-146-T5-6), `Update` вместо `Create`, ссылка та же. Страницы рендерятся все, грузятся только те, что назвал `missing` сервиса (по хэшу; правка одного разворота — две страницы). Если оставить пароль пустым, он не снимается (снять — `Change`). Хэш сцены (`share.SceneHash`, 0.32-146-21, T2-2, T2-7) считает обход структур по `reflect` вместе с размером и временем файлов фото; метки, подборки и `Gen` шрифтов в него не входят.

Состояния ссылки (`share.State`, без сети): `none` (записи нет), `incomplete` (есть `id`, нет `url`), `ok`, `changed`, `expired` (срок прошёл), `gone` (сервис ответил 404 на действие), `other` (запись другого сервиса: видна и копируется, правки — «подключите host»). Порядок проверок и случай «id без ссылки на другом сервисе» — `internal/share/state.go`, 0.32-146-T4-7.

### «Остановить» и «Продолжить»

`CancelShare` отменяет контекст хода (рендер, запросы, паузы повторов); выход из программы — тот же контекст (`StopCtx`). Остановка — не сбой: `share:done {stopped: true}`, строка в журнале одна. Опубликованная прежняя версия остаётся, новая не публикуется, временная папка удалена.

- Остановка до `Create` — записи нет, следующий «Выгрузить» начинает заново.
- После `Create` запись с `id` и без `url` — состояние `incomplete`: окно предлагает «Продолжить» (`Share` с `Days == 0`): `Update` по `id`, догружается недостающее.
- Остановка обновления — запись прежняя (с `url`), состояние `changed`: «Обновить по ссылке» делает то же заново.

Каждая запись хода идёт через `putIf`: она пишется, только пока выгрузка своя (`run` не снят, ход не отменён, путь не перезаписан другим проектом). Поэтому остановка или «Сохранить как» поверх пути не воскрешают запись прежнего альбома (0.32-146-T4-8).

### Правки ссылки

`Change` (срок «от сегодня», пароль; `PATCH`, смена пароля — с `revoke_sessions`) и `Revoke` («Отозвать ссылку?», «Нет» по умолчанию; `DELETE`, запись удаляется; 404 на `DELETE` — тоже удаляется). Обе занимают отдельный флаг `net`, пока он стоит, `Share` не стартует; идущая выгрузка — отказ. Пока идёт `PATCH`, на путь мог лечь другой проект: тогда запись не пишется и окно говорит «Изменения приняты сервисом, но альбом за это время сменился…».

### Записи: `shares.json`, отпечаток проекта

`<папка данных>/shares.json` (`prefs/shares.go`, `sharesfile.go`): `{version: 1, albums: {<путь .salbum>: запись}}`. Ключ — путь после `Clean` и `paths.Fold` (на Windows и macOS без учёта регистра); нелокальный путь — `ErrSharePath`. Запись: `origin`, `id`, `url`, `title`, `password` (открытым, чтобы «скопировать снова», design §6 п. 6), `expires_at`, `published_at`, `scene`, `gone`, `uid`. Файл читается как чужой: ≤ 1 МБ и ≤ 1000 записей, битый — `shares.json.bad` и пусто, версия новее — только чтение, запись с негодным адресом, `id` или паролем отбрасывается; 0600, атомарная запись, один замок на процесс; записи с истёкшим больше 30 дней назад сроком выбрасываются при каждой записи (0.32-146-T3-3, T3-5). Не легла на диск — запись живёт в памяти службы до выхода, ссылка видна и копируется, а ошибка показывается (0.32-146-T4-2); не стёрлась — метка `del`, `look` её не видит и повторяет стирание (T4-8). «Сохранить как» другим проектом (и сбор в папку) сбрасывает запись пути — это новая публикация (`Service.OnSaved`, С1; вызывают `files.go` и `collect.go`); у ссылки подпись «Выгружено <дата> как «<название>»».

**Отпечаток проекта (0.32-146-T4-9).** Запись о ссылке действует только для проекта, который её выдал: другой проект на том же пути (файл заменили, восстановили чужую копию) несёт другой `uid` и по её ссылке не уходит. `uid` — 128 бит hex в `.salbum` (`model.Project.UID`, `omitempty`, номер формата не меняется; описание — `salbum-format.md`). Не правка: идёт мимо `change`, без шага, `rev` и «изменён».

- **Выдаётся** (`editor_uid.go`): `NewEditor` — если годного нет; `SaveNew` («Сохранить как» другим проектом); сбор (`collect.Save`); `Restore` копии без поля; `SaveUID` — перед выгрузкой, если в файле отпечатка нет или печать не этого пути.
- **Печать `uidAt`** — первые 8 байт SHA-256 от `uid`, NUL и свёрнутого пути (`model.UIDTag`); путь в файл не пишется. Ставится только при выдаче; обычная запись (Save, автосохранение, черновик) переносит её как есть, открытие по другому пути (буква USB-диска, облачная папка) ничего не меняет.
- **Запись своя**, когда совпали `uid` записи и альбома и печать — пути альбома (`Editor.ShareIdent`, `SnapshotAt` → `Job.Unsealed`; `sharer.get`/`ownUID`). Копия шаблона (несёт печать исходника) и файл без печати — не свои.
- **Чужая запись** (`foreign`): окно показывает «нет ссылки», по записи запросов нет; «Выгрузить» спрашивает о новой ссылке («Ссылка, записанная у этого файла, принадлежит другому альбому…»), после «Да» запись затирается.
- **`pinShare`** (`Host.Pin`): до первой записи о ссылке отпечаток пишется в файл (копия до записи — `backupBefore`, затем событие `saved`); альбом сменился с момента снимка — `album.ErrUIDChanged`, «Начните выгрузку ещё раз».

Признанные ограничения (дополнения 2–4 к T4-9): (2) открытие и запись без выгрузки отпечаток не меняют; (3) выгрузка с другого пути переводит альбом на этот путь — на прежнем месте (ПК1 при синхронизации, USB под другой буквой) запись становится чужой: ссылку не показать и не отозвать, она живёт до конца срока; совет в статье F1 `share-link`: выгружать с того же места; (4) копии «перед выгрузкой» несут прежний отпечаток, «Восстановить копию» из такой делает запись чужой (вопрос о новой ссылке; Ctrl+Z возвращает своё). Файл, перенесённый проводником, ссылку в программе теряет (ключ — путь). Программа 0.31 разберёт файл с `uid` и выбросит его при первой записи — худший случай один лишний вопрос о новой ссылке.

### Подключение и токен

`config.json → share: {url}` (`prefs/shareconf.go`): origin сервиса; пусто — не подключено; чужие ключи сохраняются; при чтении адрес проходит те же правила, что при вводе, негодный даёт «не подключено» (T3-6). Адрес по умолчанию пуст (0.32-146-23). `share.ServiceURL` приводит ввод к `схема://хост[:порт]` (https; http — только loopback и только в сборке стенда `osx.DevBuild`, 0.32-146-25; хост не ASCII — отказ, 0.32-146-26).

`Connect`: адрес, токен (`albums.CheckToken`), `Health` и `List` у сервиса (на `List` токен и проверяется) → адрес в `config.json` → токен прежнего origin удаляется (0.32-146-30) → токен в `secret.Store`. Пустой токен — ошибка, чужой не подставляется. `Forget` убирает токен, адрес остаётся.

Токен (`internal/secret`, 0.32-146-8): один `Store` на процесс (`secret.System(osx.StandOn())`, `App.secrets`), ключ — origin. Хранилище ОС (go-keyring: Windows Credential Manager, macOS `security`, Linux Secret Service; служба `SosninaAlbums`) с тайм-аутом 15 с и паузой минуту после него; нет хранилища — память до выхода, окно говорит, где лежит токен (`ShareService.Store`: `system` или `session`). На стенде и под `go test` — всегда память. 401 посреди хода или правки: токен убран (`tokenLost`), записи `shares.json` целы. В `config.json`, `.salbum`, `shares.json`, журнал, события и тексты ошибок токен не попадает; в DTO только флаг `Token`. Ограничения: macOS отдаёт секрет любому процессу пользователя через `security` (принято); на Windows права 0600 не действуют, доступ задаёт ACL профиля.

### Что уходит на сервер

Уходит: страницы JPEG (1600 px, q82, без EXIF и GPS — рендер из чистого холста; белые страницы без файла); манифест — `schema`, `generator` («Sosnina Albums <версия>»), `title` (единственная строка пользователя, очищенная), `book.cover`, `book.page_mm`, по странице `n`, `role`, `type`, `sha256`, `bytes`, `w`, `h`, `blank`; рядом, не в манифесте, — `expires_at` и пароль; токен в `Authorization`; `User-Agent: SosninaAlbums/<версия>`; IP фотографа. Не уходит: пути, имена файлов фото, путь `.salbum`, отпечаток проекта, хэш сцены, таблица имён, признаки лиц, EXIF/GPS исходников. Текст 152-ФЗ при подключении — 0.32-146-28.

### Ошибки сервиса и как они видны

Тексты — `sharer/errors.go` (`errText`) по виду ошибки: 401 — «Токен не подошёл — подключите сервис заново» (при подключении — «проверьте его у владельца сервиса»); 404 по `id` — «Ссылки больше нет на сервере…» и запись `gone` (404 на health, list, create — «По этому адресу нет сервиса листалок», без пометки); 413 — «Сервис не принимает альбом такого размера»; 429 — «Сервис просит подождать»; 409 `hash_mismatch` — «Страница дошла до сервиса повреждённой…»; 5xx — «ошибка N — попробуйте позже»; сеть — «Нет связи с сервисом…»; переход 3xx, ответ не по контракту или больше 1 МБ — отдельные тексты. Сообщение сервиса (`message`) и адрес не показываются и не пишутся.

Где видны: ошибки хода — `share:done.err` (тост, окно перечитывает `ShareState`); отказы методов — отклонённый вызов (тост); подключение — строка под полем; пароль и срок — строка под своей строкой. Ссылка готова, а запись не легла на диск — в `err` приходит предупреждение (ссылка показана до выхода из программы). `log.txt`: фаза, статус HTTP, код и счётчики (`выгрузка: …`), без адреса, пути запроса, названия и `message` (design §6 п. 1, `TestShareSecretsNotLogged`).
