## Миниатюры

`library.Cache`: ключ = sha1(путь, размер, mtime), файлы `<ключ[:2]>/<ключ>_t.jpg` и `_p.jpg`; для PNG с прозрачными пикселями (`isOpaque` ложь) — `_t.png`/`_p.png` с альфой, иначе JPEG сделал бы её чёрной. `imgfile.OpenOriented` альфу не трогает (Adobe-пересчёт и поворот работают с NRGBA). У `.png` в ключе соль `|png1`: прежние чёрные JPEG-копии не подхватываются. `Cache.File` ищет оба расширения, `/media` ставит `Content-Type` по расширению файла. Один декод оригинала даёт обе копии; все декоды (миниатюры и экспорт) делят бюджет ~500 Мп в памяти (`imgfile.Budget`, файл больше бюджета идёт один); параллелизм ограничен семафором (CPU/2); одновременные запросы одного фото ждут одну генерацию. `Warm` прогревает ленту после сканирования и отменяется при новом сканировании. Ключ Adobe-фото получает суффикс `|srgb1` (старые блёклые копии не подхватываются; у остальных ключ прежний, их кэш цел); фото закрытой папки получает цвет через `imgfile.ReadColor` в `media`. Ответы отдаются с `immutable`-кэшем браузера, поэтому адреса превью в UI несут `?v=2` (`core/media.ts`).
