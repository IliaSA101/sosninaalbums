### Рабочее место: стационарный ПК + ВМ Linux (владелец 2026-10-16; отдельная задача, «когда-то на выходных», не в очереди версий)

Схема (владелец согласен): работа — на стационарном ПК в виртуальной машине; ноутбук и телефон Android — пульты (Remote Control Claude + удалённый рабочий стол). Цель ВМ — агент не может задеть файлы хоста (статьи «агент удалил нужное»), снимки для отката; в будущем — несколько проектов.

- **Железо стационарного:** i7-12700 (12 ядер: 8P+4E, 20 потоков), 32 ГБ ОЗУ, Windows 11 Pro, NVIDIA 12–16 ГБ (уточнить). ВМ: ~10–12 виртуальных ЦП, 16–20 ГБ ОЗУ (хосту ≥ 12 ГБ), диск 150–200 ГБ на SSD, динамический; видеопамять ВМ — 2–4 ГБ (3D-ускорение VMware). CUDA/ИИ на видеокарте — на хосте или WSL2, не в ВМ.
- **Гипервизор (пересмотрено 16.10 по вопросу владельца о видеокарте): VMware Workstation Pro** (бесплатен). Причина: ВМ — рабочий стол с браузером и визуальными проверками; VMware даёт Linux-гостю 3D-ускорение через видеокарту хоста (драйвер vmwgfx, OpenGL ~4.x: плавный рабочий стол, ускоренный Chromium), удобный экран, буфер обмена, подстройку разрешения. Hyper-V для обычной Linux-ВМ ускорения не даёт (GPU-P — только Windows-гостям и WSL2), рабочий стол — программная отрисовка. Прямого проброса видеокарты (CUDA, ИИ на GPU) нет ни там, ни там: это — на хосте или через WSL2. Браузерным проверкам нашего UI хватает и программной отрисовки (DOM, скриншоты), ускорение — для удобства. VirtualBox — слабее по 3D и скорости. WSL2 как основная среда не подходит: диск C: открыт на запись.
- **Система:** Ubuntu 24.04 LTS (у Claude Desktop для Linux официальная бета для Ubuntu/Debian, вкладка Code есть). Общих папок хоста с записью — НЕТ. Снимки: «чистая система», «проект готов», перед крупными шагами.
- **Удалённый доступ:** Claude Remote Control (ноутбук, приложение Android); рабочий стол — RustDesk (открытый, бесплатный, клиент Android; AnyDesk бесплатен только для некоммерческого — не берём). В Ubuntu — сеанс Xorg (с Wayland удалённый стол капризничает). Запасной путь — к хосту Windows и окно ВМ.
- **Антивирус:** в ВМ не нужен (Касперский и `.gotmp`-обход уходят); на хосте оставить, папку дисков ВМ исключить из проверки. Риски в ВМ — пакеты npm/Go и токены: токен GitHub — fine-grained, только на нужный репозиторий.
- **Аккаунт:** один аккаунт на нескольких устройствах — лимит общий; на новой машине не должно быть `ANTHROPIC_API_KEY` (иначе Claude Code платит по ключу).
- **Перенос проекта (работа агентов ~1–3 ч):** dev сейчас только локально (на GitHub — только main): перенос репозитория целиком (bundle/копия), вне git — `.claude/` (агенты, хуки, замеры), CLAUDE.md, память `~/.claude/projects/<проект>/memory`, `docs/private`, `.testphotos`, `docs/refs`. Адаптация под Linux: `check.ps1`/`build.ps1` (pwsh на Linux или sh-обёртки), Windows-пути в скриптах и тестах, `internal/osx` (проводник), gcc родной для `-race`, Wails на Linux — `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` (тег `webkit2_41`). Exe для Windows — `wails build -platform windows/amd64` из Linux или GitHub Actions; проверка exe (Фотосфера, экспорт, WebView2) — на хосте Windows. Решить с владельцем: ноутбук остаётся резервным местом или только пультом (тогда синхронизация не нужна).
- **Прочее:** Rust и Go на Linux — родная среда. Android Studio — на Linux работает; эмулятор в ВМ медленный (вложенная виртуализация), лучше настоящий телефон по `adb` через Wi-Fi. Xcode — только macOS (macOS в ВМ на ПК — нарушение лицензии Apple); сборку Mac для нашего проекта делает GitHub Actions.
- **Порядок:** VMware Workstation Pro → ВМ Ubuntu 24.04 (3D-ускорение включить) → снимок → Go 1.26, Node, Wails, Claude Desktop, RustDesk → перенос → снимок → агенты адаптируют скрипты → `check` зелёный в ВМ → снимок. Перед началом — пошаговая инструкция от меня.
